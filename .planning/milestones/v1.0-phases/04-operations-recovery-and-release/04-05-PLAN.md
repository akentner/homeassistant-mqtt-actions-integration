## Phase Goal

**As a** user running several HA instances, **I want** to re-trigger actions, see who is connected and recover devices, **so that** I can operate the setup with confidence.

This plan's slice: control. A user can set one instance or one device to observe or disabled, from a select entity on the integration page, and trust that nothing runs while it is set.

## Assumptions and defaults (visible, not silent; none are locked decisions, confirm at review)

- **Naming:** the existing `run_mode` (serial or restart) is untouched. The new concept uses `MODE_RUN`, `MODE_OBSERVE`, `MODE_DISABLED`, `device_mode` and `instance_mode`.
- **Effective mode:** the most restrictive of instance and device mode (assumption A9, confirmed in the post-research decisions).
- **Gate position:** `disabled` returns before the tracker handles the message; `observe` returns after the tracker, the trigger lookup and the `can_run` check and before the circuit breaker, so only a change that would really run is logged as suppressed (a change of a trigger without actions logs nothing).
- **Leaving disabled** (device or hub mode change that turns the effective mode from disabled into something else) clears the baseline, closes the startup window, clears the persisted baseline and subscribes the state topic again so the broker replays the retained value (assumption A17). If the broker holds no retained state, the first live message after that counts as a real change, like for a new device.
- **Storage:** two additive Store keys without a `STORE_VERSION` bump: `instance_mode` (a word) and `device_modes` (device id to word, only non-run entries). A malformed value is dropped to the default; ids that are neither owned nor mirrored are dropped at start.
- **Companion device:** identifiers `(mqtt_actions, <device uuid>)`, name = device name, manufacturer `MQTT Actions`, model `Switch device` or `Select device`, registered through the select entity's device info and attached to the subentry through `config_subentry_id` of `async_add_entities`. Do not define `async_remove_config_entry_device`.
- **Log text helper:** a public `shown(text)` in `model.py` (quoted, capped at `MAX_LOGGED_PAYLOAD_LENGTH`, with an ellipsis when cut) is the one place for broker-influenced text in log lines of the new modules; `manager.py` uses it for the observe line and `_log_ignored`.
- **Mirrors** are covered by the gate but get their select entity only in plan 04-06.
- **No SPEC.md exists; the spec-less probe was skipped.** The prohibitions above were authored by the planner from RESEARCH Pattern 5 and CONTEXT D-14 and D-15.
