## Decisions this plan implements (visible, not silent)

- **D-01:** only ha-a, ha-b and `mosq`; production untouched.
- **D-03:** a changed build is re-pinned and the checks the owner confirmed as affected are re-run (UAT04-GAP-DISPOSITION modifier full-rerun: UAT-02, UAT-03 on a fresh marker, P1-5, UAT-04); UAT-01, P2-2 and the owner-judged frontend items stay on their recorded evidence under the owner's confirmations (UAT04-GAP-DISPOSITION, UAT04-RECEIVER-GUARD).
- **D-04:** the re-pin, the restoration and the runs are scripted; no owner step.
- **D-07:** nothing is overridden; a FAIL stays a FAIL unless the owner records an override in their own name.
- **D-08 (failure rule, which stands):** a failed check is a result and is never turned into a pass; the placement clause was waived for this gap closure (D08-WAIVER, UAT04-RECEIVER-GUARD).
- **Planner decisions (documented, not owner choices):** (1) the cleanup of the 08-13 leftovers uses the restart that carries the new code, because the replay catch removes a leftover disabled row only while its device still has the native twin (research assumption A4, observed in 08-04 and 08-11), so the order restart first, marker reset afterwards is load-bearing; (2) UAT-04 must start from the failing state, not from whatever the earlier checks left: on this build UAT-02's replay turns the null tombstones into disabled_by integration (the guard disables the replayed row, the catch removes it, the record keeps disabled_by integration), which is the product working as designed, so a restoration step sits between P1-5 and UAT-04, and without it a pass would prove nothing about the receiver; (3) the restoration flips `disabled_by` on existing records only, with a backup, a validation and a restore on mismatch, and aborts instead of fabricating a record; this makes the precondition harder, never easier, and it is disclosed in `prepare.txt`; (4) the runner `run-all-scripted.sh` has no hook for the restoration, so the four checks run one by one in the runner's own order (printed by its `--list`), each after `check-preflight.sh --quick`, instead of patching the runner; (5) the guard log lines and the post-run restart are observations, never expectations.
