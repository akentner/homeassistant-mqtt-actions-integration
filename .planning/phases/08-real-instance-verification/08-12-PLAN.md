## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| broker publisher to core MQTT discovery | Any client that can publish a discovery message to the core prefix can make core create an mqtt-platform row |
| integration to the entity registry | The guard changes `disabled_by` of rows that core MQTT owns |
| documentation to users | The README and the troubleshooting page state behavior users rely on |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-35 | Tampering | The guard disables mqtt-platform rows, so a broker-side publisher could try to make it disable entities that belong to the user | medium | mitigate | Only rows whose unique id equals the id of an owned, native, non-transferred exported device, in domain switch or select, belonging to the core MQTT entry and device of that id, and only while the export is on the core prefix; foreign unique ids and mirrors are untouched (test 5); registry-only, no publish; public API only |
| T-08-36 | Denial of service | A registry-updated listener runs for every registry change of the instance | low | mitigate | The listener returns at once unless the action is create and the platform is mqtt; it is registered only while the export is on the core prefix and is cancelled on export off, on a prefix change and in async_stop (test 6) |
| T-08-37 | Repudiation | The documentation could claim behavior the code or the bench does not show | low | mitigate | The text states only what the isolation evidence and the 08-04 observation show, keeps the pinned sentences, and is run through the docs tests; it makes no claim about a restart while the export stays on the core prefix |
| T-08-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs no package |
</threat_model>
