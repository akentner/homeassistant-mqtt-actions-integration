## Phase Goal

While a legacy Discovery message is retained, a customized, enabled MQTT entity of a device that any instance keeps survives on every instance: only the owner lets the shared legacy topic go empty, and only when no online instance announces a kept row. The new fix SHA then passes CI, the full bench re-run and the CR-01 release gate, and plans 09-04 and 09-05 are re-pointed to it (REL-01).

<objective>
Make the gate meet the bench in one start: the owner waits one heartbeat interval for peers it has not heard yet (D-04), and a follower removes its waiting twins in the same run once the owner cleared the topic (D-06). Then correct the troubleshooting page and the README to the final behavior (D-19, D-03), which freezes the product as the new FIX.

Purpose: without the wait, an owner that starts together with its peers keeps everything because it has not heard them yet; without the follower re-arm, UAT-02 E1 to E3 would fail on ha-b, because its catch saw LEGACY before the owner cleared. The research timeline ends about 35 s after the start, inside the 90 s settle of `check-uat02.sh` (research Q3, Pitfall 4).

Output: the two re-arm paths with tests, the corrected docs, and the FIX commit.
</objective>

## Decisions this plan implements (visible, not silent)

- **D-04 and Claude's discretion item 4:** the current re-arm never fires once the discovery settle is done, so it cannot cover one heartbeat interval (research Q3). The catch gets a second re-arm reason, UNHEARD, with the wait `max(HEARTBEAT_INTERVAL_SECONDS + EXPIRY_MARGIN_SECONDS - presence.listening_seconds(), REPLAY_RETRY_MIN_SECONDS)`, sharing `_replay_catch_retries` and `REPLAY_CATCH_RETRIES`; with both reasons the larger wait wins. No new constant. UNKNOWN peers (older version) are never re-armed for: nothing changes in this run.
- **Orchestrator resolution 4 (early trigger):** left out. The time-based path is deterministic and covers the bench; a missed QoS 0 heartbeat keeps (fail-safe) and is visible in the count-only INFO line (research Pitfall 7).
- **D-06 and Claude's discretion item 2:** a sync-side callback, not polling: `SyncManager._on_discovery_message` compares the verdict it records with the previous one, and LEGACY to EMPTY calls `Manager.on_discovery_emptied(device_id)`. The manager re-arms only while running, after the start-up catch was armed this run, with no catch timer pending, for a native id that still has a legacy device, and within the retry bound. The owner's own clear also comes back as EMPTY; the extra bounded run only removes leftovers.
- **D-19, D-03, D-07, D-10, D-11:** the troubleshooting paragraph that said followers delete their customized entities is replaced by the final behavior and its limits; the README Limitations gain the mixed-version bullet. Docs stay English, lines stay within 120 characters.
- **09.1 D-13, D-14:** after the docs commit only `.planning/` changes until the tag; the docs commit is the FIX candidate that plan 09.2-04 fast-forwards onto main.
