<objective>
Fix the second half of review finding WR-03, the forward-compatibility row drop. Rows that fail `parse_local_record` are dropped in memory, for example a `mode` value that a newer minor release adds. Core's minor-version path even re-saves the payload at load. The next save of this release then writes only the parsed records and erases those rows permanently. The same happens to any top-level key a newer minor format adds next to `records`.

Owner decision 2026-10-21 (locked): rows that fail parse must not be erased by the next save. The owner allowed scoping this out with a rationale instead. This plan fixes it, because the fix is contained in the pure payload functions and the Store adapter, and the RESEARCH already asked to "Preserve unknown-but-valid orphan records".

Purpose: no save of this release may reduce what a newer release wrote (T-11-09, D-07 extended).
Output: preservation in the pure functions and the Store, an end-to-end Manager test, a README note, and disposition row WR-03 = fixed.
</objective>

## Artifacts this phase produces (this plan)

- local_actions.py:
  - `ParsedLocalActions.preserved: tuple[Any, ...]` (default `()`): deep copies of the stored rows that failed `parse_local_record`, in stored order.
  - `ParsedLocalActions.extra: dict[str, Any]` (`dataclasses.field(default_factory=dict)`): deep copies of the top-level keys other than `records`.
  - `dropped` keeps its meaning: malformed rows plus later duplicates.
- `local_actions_payload(records, *, preserved=(), extra=None)`: the payload is the extra keys first, then `records` = the record rows followed by deep copies of the preserved rows. An extra key named `records` can never override.
- local_actions_store.py:
  - `LocalActionsStore._preserved` and `._extra` are set by a successful load, reset by a failed load and by `async_remove_records`, and passed to every save.
  - The property `LocalActionsStore.preserved_device_ids -> frozenset[str]` collects the non-blank string `device_id` of each preserved mapping row.
  - The load warning names the kept count: "Kept %d local action records of %s that this version cannot read; they are not applied". Duplicates are logged by count separately.
