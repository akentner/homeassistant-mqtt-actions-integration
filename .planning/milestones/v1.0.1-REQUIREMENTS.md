# Requirements: MQTT Actions Integration

**Defined:** 2026-10-04
**Core Value:** A state change on one MQTT-backed device reliably triggers the configured actions on every connected HA instance, each executing them locally.

## v1.0.1 Requirements

Requirements for the Hardening milestone. Each maps to a roadmap phase. The v1.0 requirements are archived in `milestones/v1.0-REQUIREMENTS.md`; numbering of existing categories continues.

### Native Entities

- [x] **MIG-04**: A native mirror stays native after a restart, even when its config document is close to `MAX_DOCUMENT_BYTES` (review finding IN-02)
- [x] **MIG-05**: The takeover creates no duplicate entity when core MQTT replays retained legacy Discovery during startup (review finding IN-03); a test delivers the replay between the registry move and the retained clear

### Quality

- [ ] **QLT-01**: Phases 1 to 4 have a current verification; `init.manager` no longer reports them as stale
- [ ] **QLT-02**: The full test suite passes three consecutive runs; the known flake `test_delete_device_own_subscription_never_sees_state_clear` no longer occurs
- [ ] **QLT-03**: The CI and release workflows run on a pinned runner version instead of `ubuntu-latest` and pass

### Verification on Real Instances

- [x] **UAT-01**: A v0.1.0 instance next to a native instance keeps running its actions, shows no entities for migrated devices and raises no error
- [x] **UAT-02**: Re-published retained legacy Discovery plus two restarts yield no `_2` duplicates (proves MIG-05)
- [x] **UAT-03**: A command on one of two real instances runs the actions exactly once on every approved instance; an unknown payload is ignored and the state stays unchanged
- [x] **UAT-04**: The Discovery export has `enabled_by_default` false and no buttons, the core prefix yields only disabled duplicates, and switching it off clears the topics
