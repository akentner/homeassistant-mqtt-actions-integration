## Phase Goal

While a legacy Discovery message is retained, a customized, enabled MQTT entity of a device that any instance keeps survives on every instance: only the owner lets the shared legacy topic go empty, and only when no online instance announces a kept row. The new fix SHA then passes CI, the full bench re-run and the CR-01 release gate, and plans 09-04 and 09-05 are re-pointed to it (REL-01).

<objective>
Complete the wire and the second layer: every instance announces its kept legacy rows in the heartbeat (D-01), the owner publishes the migrate payload before every action that can empty the shared topic and re-checks the content and the peer signal after each await (D-09, D-10), and the takeover-path clear gets a fresh migrate too.

Purpose: plan 09.2-01 made the catch obey what peers announce; without the sending half no peer announces anything, and without the migrate a peer that starts while the gate is open loses its loaded rows (research Pitfall 1). Core 2026.9.4 keeps the registry rows of every instance when the migrate precedes the empty payload (research Q1, pinned by the core contract tests of plan 09.2-01).

Output: `Manager.kept_legacy_ids`, the field in `PresenceManager.async_publish_heartbeat`, the migrate-first catch, the fresh migrate in `_async_finish_takeover`, and their tests.
</objective>

## Decisions this plan implements (visible, not silent)

- **D-01 (sending half):** the kept set is computed at every publish from the entity registry with `takeover.keeps_enabled_legacy_row`, the predicate `remove_replay_twins` uses, so announce and act cannot drift. It also lists every held id that is not native in this run and has a legacy device (a legacy-path instance, a legacy mirror, a deferred takeover; research Pitfall 2). It uses the registry's enabled state, a superset of "enabled, loaded" (safe direction), which makes the first heartbeat after a start correct.
- **D-01, D-03 overflow:** over 16 ids or over `MAX_BROKER_MESSAGE_BYTES` (1024, characters and UTF-8 bytes) the key is omitted, which peers read as UNKNOWN; one count-only warning per start. A long non-ASCII instance name leaves room for one id only (research Pitfall 3).
- **D-09:** confirmed by research Q1 (source trace, probes, pinned contract tests), so the migrate goes out before the removal of an integration-disabled twin on LEGACY content and right before every explicit clear, only for ids whose verdict allows it.
- **D-10:** the catch re-reads the content and the peer signal after each migrate await and immediately before the removal and before the clear; the window left (a user customizes a row live between the last re-check and the publish) is the documented limit (plan 09.2-03 docs).
- **Claude's discretion item 3 (takeover-path clear):** no peer gate on `_async_finish_takeover` (research Q5: it would block the owner's cutover clear whenever a legacy peer keeps its rows, which changes the Phase 5 protocol), but a fresh migrate right before its clear. It closes the window between the pass's migrate and its clear (up to TAKEOVER_UNLOAD_TIMEOUT plus the flush) and the unconfirmed-clear retry after a reconnect, which today clears with no migrate in that run. A failed migrate returns False, so the clear stays unconfirmed and is retried, never sent bare.
- **Intentional contract changes (stated in the RED commits):** `test_heartbeat_is_published_non_retained_with_qos_0` gains the key `kept_legacy` (D-01 extends the key set). The takeover-path sequence pins gain the fresh migrate: `test_a_legacy_install_without_peers_cuts_over_after_the_settle_time` and `test_the_cutover_runs_once` (tests/test_cutover.py), `test_an_upgrade_takes_over_the_legacy_entities_and_marks_the_document` and `test_a_device_without_legacy_entities_still_gets_the_migrate_and_the_clear` (tests/test_native_start.py), `test_the_owner_cuts_over_and_a_running_follower_follows` and `test_a_legacy_peer_online_blocks_the_owner_and_going_offline_releases_it` (tests/test_cutover_instances.py). Only a migrate is inserted before a clear; no other expectation changes.
- **Out of scope by design (research A5):** the device-deletion clear (`_async_clear_discovery_topics`) stays as it is: deleting a device is meant to remove it on every instance (the empty config payload is the tombstone).
