## Phase Goal

Switch and select entities owned by the MQTT Actions config entry replace MQTT Discovery as the default way device entities are created, so every device and entity of every instance shows on the integration page. This plan builds the native entity layer for the devices an instance owns; mirrors, the migration of existing entities and the decision when to switch follow in later plans.

<objective>
Add the native Switch, Select and test-button entities for owned devices, the state they show, the commands they send and the manager state that decides which devices are native, without changing the behavior of any instance that is not in native mode (D-03, D-07, D-08).

Purpose: ENT-01 and ENT-02 are the visible half of the phase. The legacy path stays untouched and is the default until the cutover of plan 05-06 flips an instance, so this plan lands without rewriting any Phase 1 to 4 test.

Output: `switch.py`, additions to `select.py` and `button.py`, the shared `NativeDeviceEntity` and `device_info_for`, the manager state (`Device.value`, `is_native`, `async_send_state`, `async_press_test`, the persisted `native` Store key) and `tests/test_native_entities.py`.
</objective>

## Assumptions and defaults (visible, not silent; none are locked decisions)

- **The native flag is persisted state, not a test switch:** the Store gains the additive key `native` (no `STORE_VERSION` bump, the established pattern of Phase 2 and 4) holding `instance` (this instance's owned devices are native), `pending` (owned device ids whose takeover is still to run; written by plan 05-05) and `devices` (owned device ids that are native although the instance flag is not set, which is what an adopted native mirror needs in plan 05-05). This plan reads and writes all three; only `instance` and `devices` have an effect here. Plan 05-06 sets `instance`; this plan's tests seed it through the Store, which is the same path production uses.
- **Owned devices only:** `is_native` is True for an owned device when its id is in `devices` or the instance flag is set; it is False for mirrors and unknown ids. Plan 05-04 extends it for mirrors.
- **Entity names:** the switch and select take the device name (`_attr_name = None`, the base sets `has_entity_name`); test buttons keep the name `Test <friendly name>` and `EntityCategory.CONFIG` of the legacy buttons, so migrated registry entries keep their original names.
- **No optimistic state:** a command never changes the state by itself; the echo through `_on_message` is the single state source, exactly as with `state_topic` plus `command_topic` today.
