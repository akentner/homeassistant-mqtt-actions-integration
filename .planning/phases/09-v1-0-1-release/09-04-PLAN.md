v1.0.1 becomes a real release: the commit whose manifest says 1.0.1 passes UAT-02 and UAT-04 on the bench on exactly that SHA and is tagged, which closes ACCEPTED-GAP-V101 for that release (ROADMAP Phase 9, REL-01).

<objective>

Purpose: D-02 is the one irreversible step of the phase. Once a public tag has been offered by HACS, it cannot be moved without breaking installs that resolved it. The gate, the decision and the push are separated, so the owner walks through the door with all facts on the table.

Output: `09-evidence/release/pre-tag-gate.txt`, `decision.txt`, `tag-push.txt`, and the tag v1.0.1 on origin (pushed by the owner).
</objective>

## Decisions this plan implements (visible, not silent)

- **D-02 (one-way):** the tag goes on the bump commit, the exact SHA the bench verified. Tag SHA == bench SHA == bump SHA. The evidence and ledger commits after the bump are not part of the tagged tree.
- **D-04:** the owner pushes the tag only after CI and Validate are green on the bump SHA (plan 09-02). The gate here re-checks it, together with the two bench verdicts.
- **D-10:** the owner gives the go for the release notes here. Either Claude applies them after the release run is green (plan 09-05), or the owner applies them.
- **Planner decisions (documented):** (1) The tag is lightweight, like `v0.1.0` and `v1.0.0`. `release.yml` handles either kind (`gh release create --verify-tag`). (2) Claude creates the local tag before the decision, so the decision is about a concrete, verified ref. A local tag is reversible (`git tag -d`); the push is the one-way door. (3) If the owner holds, Claude deletes the local tag and the phase stops. Nothing is published.
