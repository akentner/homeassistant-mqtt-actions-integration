## Phase Goal

UAT-04 is run again on the state the owner's decision prescribes and its result is recorded with evidence, so the Phase 5 UAT debt is either closed or the remaining failure is raised again with new evidence (ROADMAP Phase 8, success criteria 4 and 5).

<objective>
Re-run UAT-04 (and UAT-02 on a guard build) with the original expectations, record the blocks, and bring the ledger, REQUIREMENTS.md, ROADMAP.md and 08-VALIDATION.md in line.

Purpose: the gap closes only through a recorded run, never through an edit of the record. The first failing run stays as history; the re-run goes to its own folder; what was changed on the bench or in the product before the re-run is part of the record.

Output: `uat-04-rerun` evidence (and `uat-02-rerun` on a guard build), block 4 recorded, a resolved Gaps entry on a pass, traceability updated.
</objective>

This plan applies for all four dispositions; the work differs. Read `~/ha-test/bin/check-uat04-iso.sh disposition` and the `applies` targets prune (document, bench-artifact), repin and guard (guard, guard-and-document) and full-rerun (a guard option with the modifier). A target that prints no is not run and is recorded as `not selected` in the SUMMARY.

## Decisions this plan implements (visible, not silent)

- **D-01:** only ha-a, ha-b and `mosq`; production untouched.
- **D-03:** a changed build is re-pinned and the affected checks re-run; the stale anchor is read against the pinned sha, and the checks that are not re-run are listed with the reason.
- **D-04:** the prune, the re-pin, the re-run and the recording are scripted; no owner step.
- **D-05:** one ledger; a re-run is recorded by hand like the first run (block, table row, evidence folder, `check-recorded.sh ID`).
- **D-07:** nothing is overridden; a FAIL stays an issue unless the owner records an override in their own name.
- **D-08:** a failed check is recorded and raised again as a gap, never turned into a pass.
- **Planner decisions (documented, not owner choices):** (1) the first failing evidence stays in `uat-04`; the re-run uses the environment variable `PHASE8_EV_SUFFIX` (value `-rerun`) to write beside it, which needs a one-line change per check script and leaves every expectation untouched, shown by a diff; (2) the ACL backup `acl.bak-phase8-04` of the first run is the pre-edit copy the ledger names, so the re-run must not overwrite it; (3) the nested gate `check-uat02.sh clean` inside `check-uat04.sh run` reads the baselines of the recorded run, so it runs with the suffix variable unset; (4) pruning the mqtt tombstones by editing the stopped registry files is acceptable on the test bench only, with copies first and checks before the start; it is what the verification report calls a clean state.
