## Phase Goal

Prove MIG-05 outside the test harness: a boot-time retained legacy Discovery replay leaves no `_2` duplicate behind the takeover (ROADMAP Phase 8 success criterion 2).

<objective>
Run UAT-02 on the native fleet at the pinned build: publish the legacy retained Discovery of the two migrated devices while ha-a and ha-b are stopped, start both, judge the registries after a graceful stop, repeat once, then clean the broker topics. Run the live-republish variant once as an observation. Record the result, then get the owner's classification of the live-republish duplicate (WR-03).

Purpose: Phase 6 fixed IN-03 under a fake broker; this is the first run against real Home Assistant cores and a real Mosquitto. The catch is a one-shot timer armed at start (Pitfall 3), so the check must publish while the instances are stopped; that is exactly the startup replay MIG-05 is about.

Output: `uat-02` evidence, ledger block 2 recorded, the WR-03 classification recorded, the bench back at its baseline.
</objective>

## Decisions this plan implements (visible, not silent)

- **D-01:** both test instances and `mosq`; the live broker is not touched.
- **D-03:** each task starts from `check-preflight.sh --quick`; the SHA and `StartedAt` go into the evidence.
- **D-04:** the whole check is scripted: publishes, stops, starts, registry evaluation. The owner only classifies the observation in Task 2.
- **D-08:** a FAIL is recorded as `issue` with a Gaps entry and the phase continues.
- **Planner decision (research open question 4):** the live-republish duplicate is run and recorded as an observation first; the owner then classifies it in Task 2 as an accepted known limit or as a follow-up gap. It never turns UAT-02 into a FAIL on its own because the success criterion names the startup replay.

## Fixture facts (verified 2026-10-04; re-read before relying)

- Migrated devices (the unique ids a legacy Discovery would create): switch "Lampe Test" `11111111-aaaa-4aaa-8aaa-000000000001` and select "Bar Select" `b6bd2c0e-6d81-49ea-8025-4bd087bd718a`, both owned by ha-a (id `3851f34f-fa67-4f3c-bba0-122465013c3d`) and mirrored natively on ha-b.
- Legacy topic: `homeassistant/device/{device id}/config`, retained, QoS 1. A replay on a core MQTT client of ha-a or ha-b creates entries with platform `mqtt`, unique id equal to the device id (switch/select) or `{device id}_test_{key}` (buttons), and an entity id ending in `_2` next to the native one.

- Baseline of the native rows: `08-evidence/00-preflight/registry-baseline-{a,b}.json` (taken from the stopped backup copies).
