## Phase Goal

A native mirror stays native after a restart even when its config document is near the size limit (plan 06-01), and a retained legacy Discovery replay during startup never leaves a duplicate entity behind the takeover (this plan, IN-03). The README stops listing both residuals.

<objective>
Add a registry-only duplicate catch to `takeover.py` and run it twice from the manager: right after the registry move and before the retained clear, and again from a timer-started background task after a quiet period, over every native owned device and native mirror on every start (D-04, D-05, D-06 and the session decision on scope). Prove both with regression tests that deliver the replay exactly where the review said it hurts, and update the README Limitations section.

Purpose: core MQTT replays retained discovery at its own pace. A replay that lands after the registry move creates a second set of `mqtt` entities (`_2` entity ids) next to the migrated ones, and the 1.0.0 code only cleans such a twin at a later takeover pass, which never runs again for a finished native device. The fix is a catch that removes the new duplicates while the migrated entries keep their registry ids and entity ids, without waiting for a settle signal that core does not expose.

Output: `remove_replay_twins` and `REPLAY_QUIET_SECONDS` in `takeover.py`, the two catches and the timer in `manager.py`, `tests/test_native_replay.py`, helper tests in `tests/test_takeover.py`, a docs test and the README edit.
</objective>

## Decisions this plan implements (visible, not silent)

- **D-04:** keep the order migrate payload, registry takeover, retained clear (a clear before the move deletes the legacy registry entries, T-5-08). The fix is a duplicate catch after the move that removes the new `mqtt`-platform entities of the device id so the migrated entities keep their registry ids and entity ids. It reuses `legacy_device`, `_legacy_entries`, `is_legacy_entity` and `_carries_the_identity`. Waiting for the MQTT discovery queue is rejected: core exposes no public settle signal.
- **D-05:** the catch runs twice: right after the move (before the clear is published) and again after the retained clear, after a quiet period, because the replay can arrive in the window between them.
- **D-06:** the replay is delivered by wrapping the publisher's retained clear so that a retained legacy Discovery is played through `async_fire_mqtt_message` just before the clear. Deterministic, no production hook.
- **D-07:** each fix starts with a failing-test commit (`test(06-02): ...`) that is red on the 1.0.0 production code, then the fix commit (`fix(06-02): ...`); the plan type is `execute` with `tdd="true"` tasks (see plan 06-01 for the commit-type note).
- **Session decision on scope (user decision 2):** the second catch covers every native owned device and every native mirror on each start, not only pending devices, guarded by `legacy_device(...)`. Core publishing one empty retained discovery on a native device's legacy topic when a loaded duplicate is removed is accepted (research assumption A2). The catch never publishes migrate payloads for mirrors (T-5-02).
- **Research warnings honored:** the regression tests use the default `mqtt_mock` for the window before the clear (the clear that the mocked client loops back is retained and core drops it, so a replay before it is not cleaned by core, Pitfall 2) and `retain=False` for every replay (core ignores a second retained message per topic, Pitfall 3).
- **Quiet period as a timer, not a sleep (planner decision, Claude's discretion):** research proposed a background task that sleeps. Sleeping hangs every test that uses the `freezer` fixture together with a native instance (verified: an `asyncio.sleep` under that fixture never returns), and would add the wait to every test that blocks on background tasks. The cutover already uses `async_call_later` and a test helper that fires time; the catch follows that pattern, so no conftest change is needed. The delay is `takeover.REPLAY_QUIET_SECONDS`, 5.0 seconds, which equals the discovery cooldown of core MQTT.
- **Not planned:** an entity registry event watcher that would also catch a replay minutes after the start. Research marked it an optional hardening that is not locked, and CONTEXT lists nothing for it.
