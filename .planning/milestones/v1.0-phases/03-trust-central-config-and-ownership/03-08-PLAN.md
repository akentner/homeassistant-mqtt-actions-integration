Verified at planning time (exact lines in `config_flow.py` as of this plan):
- `async_step_delete_device` (line ~211): `name` is the raw subentry title. Used by both device types (inherited from `_DeviceSubentryFlow`).
- `SelectSubentryFlow.async_step_menu` (lines ~450-454): `name` is the raw draft name, and each `options` line is `- {friendly_name} ({state_value})` with both parts raw. Only the two user-text parts get escaped; the `- ` marker, the parentheses and the `\n` join are structure and stay as they are.
- `SelectSubentryFlow.async_step_remove_confirm` (lines ~594-595): `friendly_name` and `state_value` are raw.
- Found while verifying, same class and same file, therefore in scope: `SelectSubentryFlow.async_step_edit_option_details` (line ~573) passes the raw `state_value` for its description. The UAT list did not name it.
- Not changed on purpose: the option chooser labels (`SelectOptionDict` label) and the form suggested values render plain text, so escaping would show backslashes. The `field`, `error` and `device_ids` placeholders feed form error alerts, not a Markdown description; they are outside G-03-2 and were not checked against the frontend.
- Translations (`en.json` and `de.json`): every one of the five affected descriptions uses the placeholders as bare words (for example "Delete the device {name}?"), never inside backticks, emphasis, links or quotes. A single `escape_markdown` pass therefore cannot double-escape. Task 2 adds a guard test so this stays true.
