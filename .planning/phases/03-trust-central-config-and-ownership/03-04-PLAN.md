## Phase Goal

**As a** user with several HA instances, **I want** devices created on one instance to appear on the others once I approve them, **so that** every instance runs the actions locally.

This plan's slice: the follower. Another instance's devices appear here as read-only mirrors that track state and run nothing. Approval (plan 03-06) is the only thing that will ever make them run.

<objective>
Add the follower side of `SyncManager`: a validated, pinned, cached mirror for every foreign document (D-06, D-08, D-14, D-15, D-17), kept in `Manager.mirrors` with its own state and test subscriptions, persisted in the Store, and inert by construction until approval exists.

Purpose: SYN-02 and SYN-03 (follower side), the mirror half of TRU-01, the ingest half of TRU-03 and the mirror part of STA-03. Removal of mirrors is plan 03-05; approval and execution are plan 03-06.

Output: changes in `sync.py`, `manager.py`, `actions.py`, `const.py`, issue texts in en/de and the tests named in the tasks. Implements D-06, D-08, D-13 (local state stays local), D-14, D-15, D-17 and D-19.
</objective>

## Assumptions and defaults (visible, not silent; none are locked decisions, confirm at review)

- **Open Question 3 default (D-06 reading):** only the structural gate (strict parse, `cv.SCRIPT_SCHEMA` on every action list, size, depth) drops a document here. `async_validate_actions_config` (deep, instance dependent: unknown local `device_id` and the like) does not drop a document; it informs at approval time and again when a Script is built (plan 03-06). Otherwise a follower lacking one local device would never see the mirror and never learn why. A statically denied service does not drop the document either: the mirror is stored and flagged `denied` so it can be shown as blocked (A6).
- **Self-derived edge cases (no SPEC.md exists, the spec-less probe was not run):** the prohibitions above and the behavior edge cases were authored by the planner from RESEARCH and CONTEXT.
- **No Script for mirrors in this plan:** the gate is closed by construction because `ActionRunner.can_run` is false for a device without a built Script; plan 03-06 adds the approval-aware build. Mirrors created here are therefore safe by default.
- **Restart behavior:** a mirror created live by a document has no startup window; only a mirror restored from the Store at start gets `startup_pending` (same rule as owned devices). Approving later never retroactively runs anything (STA-04).
- **A2 tunables:** `MAX_MIRRORS = 100`, `MAX_SCHEMA_TOO_NEW_ISSUES = 10`. Worst-case Store growth is bounded by `MAX_MIRRORS * MAX_DOCUMENT_BYTES`.
- **Stored form:** the Store keeps the received payload text per mirror (one code path: it is parsed again at load, the stored hash is never trusted). Baselines and tripped hashes of mirrors reuse the existing `last_acted` and `tripped` maps; approvals get their own key in plan 03-06.
- **Order of messages:** ingest runs in background tasks that take the manager's FIFO lock in arrival order, so two quick documents for one device apply in order.

| Boundary | Description |
|----------|-------------|
| Broker to follower ingest | Any client with write access can publish a config document for any device id |
| Store to follower runtime | Cached mirror payloads are read back at start |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-14 | Spoofing | a forged document creates a mirror that acts like a real device | high | mitigate | A mirror builds no Script and cannot run anything until the user approves its exact action hash (plan 03-06); strict parse and structure gate before anything is stored; static denylist result recorded |
| T-03-15 | Spoofing | a second owner takes over a pinned device | high | mitigate | The first owner is pinned; later claims are ignored and reported in `owner_conflict_<id>`; no takeover path exists in this phase (D-17) |
| T-03-16 | Denial of service | flooding with document topics (unbounded mirrors, Store growth, Repairs issues) | high | mitigate | `MAX_MIRRORS`, `MAX_DOCUMENT_BYTES`, `MAX_ACTION_DEPTH`, `MAX_SCHEMA_TOO_NEW_ISSUES`, conflict issues only for existing mirrors, broad exception guard at the ingest boundary |
