## Decisions this plan implements (visible, not silent)

- **CONTEXT carried forward (research Pitfall 16):** keep per-device isolation, accumulate the partial count before the exception, flush when `removed > 0` or an exception occurred; never catch inside `takeover.remove_replay_twins` and return 0.
- **Planner decision (how the count crosses the boundary):** `takeover.remove_replay_twins` stops at the first failing row, finishes the emptied-device cleanup and the count line, and raises `ReplayTwinsError(removed)` chained from the original error. This is not a catch that hides the error: the caller sees the failure, its type and the count. A failure of the cleanup itself replaces the error (accepted: the caller still flushes on the generic error).
- **Planner decision (return shape):** `NativeMigration._remove_replay_twins` returns `TwinRemoval(removed: int, errored: bool)` (a NamedTuple); the takeover path keeps ignoring the result, because its own flush already runs whenever a takeover is DONE.
- This is a fix on top of the moved module; the move of plan 10-04 is untouched (roadmap: never a fix in the move plan).
