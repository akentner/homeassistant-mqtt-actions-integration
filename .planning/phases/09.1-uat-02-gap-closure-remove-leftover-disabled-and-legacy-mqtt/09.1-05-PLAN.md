## Decisions this plan implements (visible, not silent)

- **D-12 and Phase 9 D-08:** preflight as in Phase 9 (`preflight.sh stage1`, `stage2`, `check-preflight.sh`), plus a registry backup with both instances stopped to `~/ha-test/_backup-pre-phase9.1-<UTC stamp>` (mode 0700, pointer `~/ha-test/.current-backup-phase9.1`). D-16's `preflight/` is realized as `00-preflight/`, the fixed name of the unchanged scripts.
- **D-09:** the stage2 start is the first start of the fix build and the recorded heal start. Before it, Task 1 proves that no intermediate tree ever started: the StartedAt values still equal `heal-start/bench-before-fix.txt`, or the pre-state still holds the leftovers. The heal is judged on the flushed registries after a graceful stop.
- **D-13 (tag SHA == bench SHA == FIX):** `pin()` reads HEAD from the `.git` files of this checkout, and main carries `.planning` commits after FIX. So HEAD is detached at FIX with `git update-ref --no-deref HEAD <FIX>` for exactly the pin window (stage1 and stage2) and restored with `git symbolic-ref HEAD refs/heads/main` right after. FIX and main differ only under `.planning/`, so the working tree, the index content and the bind mount do not change. `build.txt` then names FIX itself, and its branch reads `(detached)`. That is the planner's answer to research Pitfall 5.
- **D-10 and user decision 1:** run (a) writes into `uat-02/` with the suffix unset, which is the folder that `reseed-tombstones.sh` and `check-uat04.sh` read. Run (b) writes into `uat-02-null/` with `PHASE8_EV_SUFFIX=-null`. `README.txt` and the ledger state that `uat-02/` is the integration start.
- **D-12:** UAT-04 starts from the restored null-tombstone state, proven by the exact line `regression state before UAT-04: ha-a null tombstones switch=1 select=1; ha-b null tombstones switch=1 select=1; live mqtt rows a=0 b=0`. ha-c stays stopped (Phase 9 D-07).
- **Planner decisions (documented):** (1) Phase 9's failure rule holds: checks continue after a FAIL when their preconditions hold without a hand edit, otherwise they are `blocked` with the reason. A heal-start FAIL stops the plan, because every UAT-02 baseline would ABORT on the leftovers. (2) The guard lines, the deferred-takeover warning (research Pitfall 8) and one post-UAT-04 restart are observations, never expectations. (3) A lost marker approval on ha-b is a finding: stop and report, never re-approve silently.
