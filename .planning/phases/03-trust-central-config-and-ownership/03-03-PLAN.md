## Phase Goal

**As a** user with several HA instances, **I want** devices created on one instance to appear on the others once I approve them, **so that** every instance runs the actions locally.

This plan's slice: the owner-facing flows. Deleting a device says plainly that it disappears everywhere, and removing the hub no longer silently deletes devices other instances still use.

<objective>
Add the explicit all-instances delete confirmation to both device flows (D-16) with a small instance-presence cache behind its wording, and replace the Phase 1 hub removal with a keep-or-delete choice stored in a hub OptionsFlow (D-11).

Purpose: SYN-06. The broker-side removal order already exists (plan 03-02); this plan makes the user-facing door honest.

Output: changes in `config_flow.py`, `sync.py`, `manager.py`, `__init__.py`, `const.py`, en/de texts and the tests named in the tasks. Implements D-11 and D-16.
</objective>

## Assumptions and defaults (visible, not silent; none are locked decisions, confirm at review)

- **Open Question 1 default:** the generic Home Assistant subentry delete (websocket command and frontend dialog) cannot be vetoed and its dialog text is not customizable (A4). Both paths tombstone everywhere through the reconcile removal. The all-instances wording lives in this plan's confirm step, in the README and in a manual UAT row (plan 03-07).
- **Open Question 5 default (A11):** the confirm step says "all connected instances" and gives the count of other instances seen online; there is no instance-name information document (full roster is Phase 4, OPS-03). D-16's "listing the instances as far as known" is met as a count.
- **Open Question 6 default:** there is no extra hub-level opt-in switch; per-device approval (plan 03-06) stands as the opt-in of D-01. The wording "local opt-in flag" in `.claude/CLAUDE.md` is reconciled in the README trust section (plan 03-07) and flagged to the user in the planning return.
- **Self-derived edge cases (no SPEC.md exists, the spec-less probe was not run):** the prohibitions above and the behavior edge cases were authored by the planner from RESEARCH and CONTEXT.
- **Presence cap:** `MAX_TRACKED_INSTANCES = 256` (tunable, A2).
- **D-11 default keep:** the choice is stored before removal because Home Assistant runs `async_remove_entry` after unload and offers no dialog. The option lives in an OptionsFlow (not a reload-on-change variant); saving it triggers the normal update listener, whose reconcile is a no-op.
