## Decisions this plan implements (visible, not silent)

- **D-09 (module cut):** whatever only the migration uses moves; NativeState stays in Manager; `presence.py` keeps supplying only the heartbeat field (`kept_legacy_ids` stays in Manager because presence calls it, and with it `_kept_failure_logged`); `takeover.py` stays registry primitives. `_schedule_native_reload` and `_reload_scheduled` stay (research seam table).
- **Public surface (Claude's discretion, kept small):** `async_takeover()` (was `_async_native_takeover`, the caller holds the lock), `arm_duplicate_guard()` (was `_arm_duplicate_guard`), `arm_timers()` (the cutover arm, then the replay-catch arm, the order of today), `stop()`, `async_retry_unconfirmed_clears()` (the caller holds the lock), `on_roster_changed()`, `on_discovery_emptied(device_id)`, and the per-run set accessors `is_deferred(device_id)`, `clear_pending(device_id)`, `defer_for_run(device_id)`, `forget(device_id)` (research ARCHITECTURE seam table). Every other moved method keeps its exact private name, so patch targets only change their owner.
- **Planner decision (no private access across classes, Ruff SLF001):** NativeMigration reads Manager only through public members. Where a needed member is private today, Manager gets a one-line public accessor that returns or calls it unchanged: `native_state` (property, returns `self._native`), `publisher` (property, returns `self._publisher`), `async_save_now()` (awaits `self._store.async_save(self._data_to_save())`), `schedule_save()` (calls `self._schedule_save()`), `test_message_handler(device_id)` (returns `partial(self._on_test_message, device_id)`). No existing Manager member is renamed.
- **Planner decision (`_async_attempt`):** the module-level helper moves as it is to `mqtt_gateway.py` as `async_attempt` (it wraps one MQTT step and logs an unavailable client), because NativeMigration cannot import from manager.py at runtime (manager.py imports native_migration.py). manager.py imports it and its call sites change only the name.
- **Presence and sync stay byte-identical:** Manager keeps `on_roster_changed()` and `on_discovery_emptied(device_id)` as one-line delegators, so `presence.py` and `sync.py` need no edit.
- **D-10 interpretation (stated, not silent):** D-10 allows the `_cancel_replay_catch` access and the patch targets that must point at the new module. Since 09.2 the suite has four more references of the same kind to members that move: `manager._replay_catch_retries` (an access path), `Manager._async_replay_catch` and `manager_module.async_call_later` (monkeypatch targets), and `Manager._on_replay_catch_due` (the identity the timer spy filters on); plus the conftest monkeypatch target `CUTOVER_SETTLE_SECONDS`, without which every test would arm the cutover timer. They change the same way: only the owner object or module changes; parameter names, bodies and assertions stay. No other test line changes; the acceptance criteria check it.
- **Research Pitfall 8:** `@callback` methods stay synchronous, the start-up order stays, `patch(` targets are audited, one mutation check per moved function.
