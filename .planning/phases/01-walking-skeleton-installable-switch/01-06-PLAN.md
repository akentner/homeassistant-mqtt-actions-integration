## Phase Goal

**As a** Home Assistant user, **I want to** create a Switch device whose MQTT state changes run my configured actions, **so that** I need no YAML automation.

This plan's slice: installability and trust. Anyone can install it through HACS, every push proves itself in CI, and the user manually confirms the frontend behavior no automated test can see.

<objective>
Add the distribution files (hacs.json, LICENSE, README, brand icon), the CI and Dependabot configuration with SHA-pinned actions, and a test that keeps them true; then publish the repository through a human-action gate and prove CI green on the pushed branch.

Purpose: FND-01 and FND-02 are only real when a stranger can add the repository to HACS and the pipeline passes on GitHub, not only on this machine. Publishing a repository is an external, visible act, so it is a human-action checkpoint (D-12). Implements D-12 and D-13 (hacs.json floor).

Output: distribution and CI files, `tests/test_repo_structure.py`, a public repository, a green Validate and CI run for the head commit, and the consolidated manual UAT list.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local working tree to public GitHub | Everything tracked, including .planning documents and history, becomes public |
| GitHub Actions runners | Third-party action code runs with the workflow's token |
| README to integration users | Users decide broker exposure based on what the documentation tells them |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-16 | Tampering | CI supply chain (action refs, token permissions) | high | mitigate | Every action pinned by full commit SHA and re-resolved at write time; workflow-level permissions empty; persist-credentials false on checkout; Dependabot for github-actions and uv; the structure test fails the build if any of these regress |
| T-01-17 | Information disclosure | publishing the repository, .planning documents and git history | high | mitigate | Publication is a human-action gate (Task 2) with an explicit note that .planning becomes public; a secret-pattern scan over tracked files runs before any push; no credentials are stored in the repository (Bitwarden convention) |
| T-01-18 | Elevation of privilege | users unaware that state-topic write access triggers actions | medium | mitigate | README Security section states the trust model, recommends broker ACLs and warns against device_id targets; full ACL example is TRU-04 in Phase 3 |
| T-01-SC | Tampering | apt install of mosquitto in CI | low | accept | Test-only broker from the runner's distribution repository; no runtime dependency is introduced and uv installs stay behind the locked lockfile |
</threat_model>
