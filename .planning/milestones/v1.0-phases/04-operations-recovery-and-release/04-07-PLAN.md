## Phase Goal

**As a** user running several HA instances, **I want** to re-trigger actions, see who is connected and recover devices, **so that** I can operate the setup with confidence.

This plan's slice: support. A user can attach a diagnostics file to a bug report without leaking their automations, entity ids or broker credentials.

<objective>
Add the Home Assistant diagnostics platform for the config entry: an allow-list build of hub options, roster and device list with shortened ids, a public `approval_state` on the manager, and tests with sentinel strings that prove what never leaves (D-17).

Purpose: OPS-04. The file is meant to be shared; the actions of a mirrored device are another instance's content and an owned device's actions can hold anything, so the safe form is to name what is included instead of removing what is not.

Output: `diagnostics.py`, `ApprovalState` and `Manager.approval_state`, and `tests/test_diagnostics.py`. Implements D-17.
</objective>

## Assumptions and defaults (visible, not silent; none are locked decisions, confirm at review)

- **Output shape (Claude's discretion):** keys `integration_version`, `hub` (`base_topic`, `instance_name`, `instance_id` shortened, `instance_mode`), `roster` (a list of `id` shortened, `name`, `version`, `last_seen`, `online`) and `devices` (a list of `uuid`, `kind`, `origin` as owned or mirror, `owner` shortened, `mode`, `effective_mode`, `approval`, `breaker` as ok or tripped, `rev`, `hash`).
- **Device names are left out** of the device list: D-17 lists uuid, kind, owner, mode, approval, breaker, rev and hash only, and a mirror's name is broker-supplied text. The uuid is enough to correlate. Peer instance names stay in the roster, as D-06 and D-17 name the roster.
- **Shortening:** the first 8 characters of an instance id, a module constant of `diagnostics.py`.
- **Hash:** the content hash of the shared content (owned: computed from the spec; mirror: the recorded hash), never the approval hash and never any action text.
- **Approval words:** `owned`, `approved`, `pending`, `blocked` (a statically denied mirror) and `no_actions` (nothing to approve); `unknown` for an id that is neither owned nor mirrored.
- **`hassfest` dependency check** accepts the `homeassistant.components.diagnostics` import because the integration ships a `diagnostics.py` (research Pattern 9); no manifest change.
- **No SPEC.md exists; the spec-less probe was skipped.** The prohibitions above were authored by the planner from RESEARCH Pattern 9 and CONTEXT D-17.
