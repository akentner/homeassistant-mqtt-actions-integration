<objective>
Fix review finding WR-01. Today `sync._async_remove` forwards every empty config payload of a non-owned id as `MirrorRemovalCause.TOMBSTONE`, and `Manager._async_discard_tombstoned_records` then saves the local Store without that device. An empty payload carries no owner, so any broker client (MQTT Explorer, a script, a bridge) can destroy local-only data on every instance, while the mirror itself self-heals when the owner republishes.

Owner decision 2026-10-21 (locked): keep the records and mark them inactive. The mirror is removed at once, as today. The local records stay in the Store like after a prune, shown as not mirrored in the editor, and the user removes them explicitly. When the device returns, they apply again. The grace-timer alternative from the review is NOT implemented. Adoption, explicit removal of a customization and hub removal still delete.

Purpose: close the permanent, silent data-loss path (T-11-47) and reconcile the user docs that promised a tombstone discard (D-05).
Output: the code change with regression tests, the user docs and docs test, and disposition row WR-01 = fixed. Plan 11-23 runs in the same wave and carries the amended rule into the release-notes draft, REQUIREMENTS MIR-08, ROADMAP success criterion 5 and 11-CONTEXT.md. The plan was split this way in the revision after the plan check, to keep this plan within the per-plan file budget.
