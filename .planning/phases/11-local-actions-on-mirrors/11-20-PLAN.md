<objective>
Fix the first half of review finding WR-03. The `local_actions_unreadable` issue promises that a damaged file is not applied, editing is refused and the file is not changed. The code only keeps that promise when `async_load` raises (a newer major version). Two cases bypass it:
- A JSON-corrupt file: Core renames it to `*.corrupt.<time>`, raises its own `storage_corruption` issue and returns `None`. `async_load_records` treats `None` as no records and sets `_loaded = True`, so replaced and muted triggers silently run approved owner actions again.
- Valid JSON with the wrong shape: it loads as empty with only a warning, and the next save (any edit, a label refresh, an adoption discard) overwrites it.

Owner decision 2026-10-21 (locked): treat shape-invalid as unreadable (raise the instance issue, keep `_loaded = False`, refuse saves). Handle "load returned None while a `.corrupt.*` sibling exists" as unreadable too. Align the issue text (en/de) and docs/troubleshooting.md with what really happens for a JSON-corrupt file. The forward-compatibility half of WR-03 (rows that fail parse must survive the next save) is Plan 11-21, which also sets the disposition row.

Purpose: make the refusal (T-11-09) and its visible issue (G-02) hold for every unreadable shape, not only for a newer major version.
Output: Store changes with Store, Manager and hub-removal regression tests, plus aligned en/de issue text and troubleshooting.
</objective>
