# Phase 9.2 Plan 02: Peers announce their kept rows, and the owner migrates first and re-checks before it empties the shared topic (Summary)

**Every heartbeat now carries `kept_legacy`. The list comes from the registry by the same predicate the catch keeps by, so it is right from the first heartbeat after a start. When the list does not fit, the key is left out and the heartbeat still goes out. The owner publishes the migrate payload before every action that can empty the shared core-prefix topic, and after each migrate it reads the content and the peer signal again. The takeover-path clear also gets a fresh migrate, on the pass and on the retry.**

## Accomplishments

- `manager.py`:
  - `kept_legacy_ids()` returns the sorted held ids (owned or mirrored) that have a legacy MQTT device and meet one of two conditions:
    - they are not native in this run, or
    - they keep an enabled legacy row (`takeover.keeps_enabled_legacy_row`).
  - Without an MQTT entry it returns `[]`. On any error it returns `None` after a warning without content.
  - `_async_replay_catch` now runs in this order:
    1. Read the content and the peers.
    2. Migrate every LEGACY id the gate lets go.
    3. Read again. The may-empty set is the fresh verdict's `remove_disabled` ids whose fresh content is EMPTY or whose migrate went out.
    4. Remove, with no await before this step (WR-01), then flush.
    5. For each id: check `_may_clear`, migrate, check `_may_clear` again, clear.
  - The INFO lines and the UNKNOWN re-arm did not change.
  - `_async_publish_migrates` and `_may_clear` are new helpers.
  - `_async_finish_takeover` publishes a fresh migrate before its clear. If that migrate fails, it returns False, so the clear stays unconfirmed and is retried later. A bare clear is never sent.
- `presence.py`:
  - `async_publish_heartbeat` adds `kept_legacy` when the list has at most 16 ids and the payload passes `within_size_cap`. Otherwise the key is left out.
  - `_kept_overflow_logged` limits the count-only warning to once per start. It is reset in `async_start`.

- **Found during:** Task 1 GREEN.
- **Issue:** The test's fresh install runs the legacy path, so the mocked paho client loops the device's legacy discovery back to core. - **Files modified:** `tests/test_presence.py`
- **Commit:** `61fb39d`. This is a separate test commit between RED and GREEN, so the GREEN commit only touches product files.

**2. [Structure] The catch's migrates are in a helper**
- `_async_publish_migrates(device_ids)` wraps the planned `_async_attempt(partial(self._publisher.async_publish_migrate, device_id), ...)` per id and returns the ids where the migrate went out.
- Without a publisher, no id counts as migrated, so no LEGACY twin is removed. Behavior matches the plan.
