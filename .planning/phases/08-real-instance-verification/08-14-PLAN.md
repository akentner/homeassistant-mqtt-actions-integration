## Phase Goal

The Phase 8 verification record matches what really happened: UAT-04 passed on the prescribed state or is still open with new evidence, the archived Phase 1 to 4 reports are current again, and the final gate says so (ROADMAP Phase 8, success criteria 4 to 6; decisions D-05, D-06).

<objective>
Finish the gap closure: make the final gate and its anchor file current, document the bench state, refresh or re-run the archived reports, re-verify Phase 8 itself, and gate the result.

Purpose: plans 08-11 to 08-13 changed the ledger, the evidence and possibly README.md, docs or the product. Every one of those is a covered file of some archived report, so their digests are stale until the verifier or a digest refresh has run, and `check-final.sh` cannot pass before that. This plan does it in the one order that avoids a circle: finalize every covered file first, then run the verifiers, then commit only the reports.

Output: a current gate, a current script copy, regenerated archived reports (Phases 1 to 4), a regenerated `08-VERIFICATION.md`, and a final gate that prints PASS.
</objective>

## Decisions this plan implements (visible, not silent)

- **D-03:** the stale anchor is read against the recorded (and for a guard build re-pinned) sha before anything is verified.
- **D-05:** the ledger is final before the verifiers start and is not edited afterwards.
- **D-06:** the archived reports are refreshed by the verifier, or by a digest refresh from `verification.fingerprint` with a dated note when only documentation or the ledger changed (the Phase 4 precedent); the reports are never edited by hand.
- **D-07:** a UAT-04 override exists only in the owner's own name; this plan never supplies one.
- **D-08:** a gap that is not closed by evidence stays a gap in the report.
- **Planner decisions (documented, not owner choices):** (1) the discriminator between a verifier re-run and a digest refresh is `git diff --stat b7f52b34a1e8d6afbf6e1ac75f3b92bbbe54a8f3 HEAD -- custom_components tests .github`: non-empty means the code or tests that the reports judged changed, so the verifier must judge again; (2) the Phase 8 report is regenerated in every case because its covered files include the ledger and the new plans; (3) no ledger edit follows the verifier runs.
