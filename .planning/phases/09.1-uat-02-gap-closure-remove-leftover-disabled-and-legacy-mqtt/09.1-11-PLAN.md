## Decisions this plan implements (visible, not silent)

- **Planner decision: the optional CR-01 observation is planned, not dropped.** It runs after every verdict of plans 09.1-09 and 09.1-10 is recorded, so it cannot change a result. It runs only when all four fix2 verdicts are PASS; otherwise `outcome.txt` reads `skipped` with the reason, and only the clean-bench checks run.
- **How the case is built (planner decision):** a live replay, the documented known limit WR03-LIVE-REPLAY (D-07): publishing the legacy payload retained while both instances run makes core create the `_2` rows, the guard disables the switch twin, and the replayed test buttons stay enabled until the next start. One replayed button per instance is renamed through the WebSocket API (`config/entity_registry/update`), which makes it customized (`_is_customized`) and kept, so `keeps_an_enabled_row` is true. The retained legacy message stays, so the next start reads LEGACY. This is the scenario of `test_the_catch_keeps_an_enabled_customized_button_next_to_a_disabled_twin_on_legacy_content`.
- **Outcome classes (fixed before the run):** per instance, `exercised-as-expected` when no "postponed" line for this start exists, the renamed button still exists enabled with NAME, the integration-disabled switch twin still exists, and TOPIC still holds a non-empty retained payload; `contradicts` when the renamed button is gone or TOPIC was cleared; otherwise `not-exercised` (for example the takeover was postponed, research Pitfall 8, so the catch never evaluated the device). Overall: `contradicts` if any instance contradicts, else `exercised-as-expected` if at least one instance is, else `not-exercised`.
- **Cleanup is product behavior first, a backup only as fallback:** reset NAME to null (so no customized deleted record remains), clear TOPIC with an empty retained publish, restart once (EMPTY after the settle removes the disabled twin and the emptied legacy device). Only if `check-uat02.sh clean` still FAILs after a second restart are the four registry files of the pre-observation copy restored with both stopped, recorded in `bench-notes.txt`. This is bench hygiene after all verdicts, never a result, and D-09 (heal start) is not affected.
