## Receiver-side design (planner decisions, with the alternatives weighed)

Why the receiver is not covered today, from `manager.py`: `_sync_export_guard` arms the guard only while this instance's own export is on and its prefix equals `gateway.discovery_prefix()`; `_export_guard_ids` returns the owned native devices only; `async_start` and `_async_apply_export_options` are the only callers that arm it. A receiver (an instance that only follows the device, or an owner whose own export is off) has neither condition.

**Chosen design, a registry-driven guard that is armed whenever the manager runs:**

- **R-1, ids.** The ids the guard protects are the native devices this instance holds: `_native_device_ids()` (owned devices and mirrors for which `is_native` is true) without the ids in `sync.transferred_away`. The set is read at event time, so a mirror that appears later is covered. A legacy device, a device that waits for the takeover pass and a device whose takeover was deferred are not native (`is_native` is false for them), so their live legacy rows are never candidates.
- **R-2, arming.** Armed at the place where `async_start` arms it today (after `_async_native_takeover`, before the owned discovery is published) and disarmed in `async_stop`. It no longer reads the export option or the prefix, and `_async_apply_export_options` no longer calls it. A row for a native id can only come from a discovery payload on the prefix core MQTT listens to, so the prefix comparison was only ever a proxy.
- **R-3, triggers.** One sweep when armed (rows that exist after a restart, including rows core created before the manager started). Then a registry listener that looks only at `create` events: of an mqtt-platform entry (core just created the duplicate) and of a mqtt_actions switch or select entry (the native twin just appeared, which closes the ordering gap when the duplicate came first). Both schedule one pass for that unique id on the next loop iteration, never nested in core's entity creation. An `update` never triggers a pass.
- **R-4, one pass for one id (takeover.py helper).** The core MQTT device of the id (`legacy_device`); the entries `_legacy_entries` returns (platform mqtt, the core MQTT config entry, that device, exact identity shape) narrowed to unique id equal to the id, domain switch or select (never a test button), `disabled_by` None, and a native twin: an entry of the same domain, platform mqtt_actions and the same unique id under this config entry. This is the definition of a duplicate that the replay catch (`remove_replay_twins`) already uses, so an entry without a twin is no duplicate. Each candidate gets `disabled_by` integration through `er.async_update_entity` and the count is returned. Never remove, never enable, never touch the twin, never publish.
- **R-5, log.** One content-free INFO line with the count when it is non-zero (no id, name, payload or entity id), so the bench can show that the guard acted on a receiver. A failure is swallowed with the existing content-free warning.

**Alternatives weighed and rejected.** (a) Keep the arming tied to the own export and add a second arming "while a native mirror exists": an owner whose export is off still meets a foreign or stale retained export, and a second rule doubles the cases. (b) Observe the export payload on the core prefix with one subscription per native id: a new subscription on a busy prefix, a race with core's own subscription, no reliable way to tell an export from legacy discovery by shape, and no safety gain, because the filter above is identical. (c) A hub option or a flag in the config document: user-visible surface (translations), a wire change, stale owner-judged frontend checks. (d) Disable a row in the replay catch before it removes it, so removals leave a disabled tombstone: redundant once the guard is armed, and it does nothing for rows that already exist.

**Trust model (the stack rule: nothing from the broker executes without opt-in and validation).** The guard executes nothing and publishes nothing. It can only lower an existing row to disabled. A broker publisher or a hostile mirror document can at most make the guard disable a row that its own discovery payload created, because a candidate needs the exact core MQTT device identity of an id this instance holds natively and a native twin. A mirror id reaches `self.mirrors` only through `parse_document`. User-disabled rows keep their state. `docs/broker-acl.md` needs no change: no new topic is read or written.

**Edge cases and what the plan does with them.** Exporter switches the export off: the clear removes loaded (enabled) entities; guard-disabled rows were never loaded, so they stay as disabled rows until the next start, where the replay catch removes them and the removal leaves a tombstone with `disabled_by` integration, so the next export arrives disabled (cycle test, README sentence, bench observation in plan 08-18). Restart ordering: sweep at arm plus listener plus the twin trigger. Fresh install: core creates the row disabled (`enabled_by_default` false), `disabled_by` is not None, no update happens. Idempotence: a second pass finds nothing enabled. A legacy Discovery replay on a native instance now has its switch or select row disabled by the guard before the catch removes it, so the tombstone the catch leaves carries `disabled_by` integration instead of null; this is an improvement and it is why plan 08-18 restores null tombstones before UAT-04.

| integration to the entity registry | The guard changes `disabled_by` of rows that core MQTT owns |
| remote mirror document to this instance | A mirror id and its native flag come from the broker through `parse_document` |
| documentation to users | The README and the troubleshooting page state behavior users rely on |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-48 | Tampering | The guard is now armed on every native instance and also covers mirrors; a filter that is too wide would disable a live legacy entity or an unrelated entity | high | mitigate | Candidates need all of: a native id this instance holds (owned and not transferred away, or a native mirror), the core MQTT config entry, the core MQTT device (mqtt, mqtt_actions_<id>), domain switch or select, unique id equal to the id, `disabled_by` None, and a native twin under this config entry (the replay catch's definition of a duplicate); disable only, never remove or enable; legacy, pending and deferred devices are not native; trust matrix tests G3 and the interlock test E1 pin each exclusion |
| T-08-49 | Spoofing | A broker publisher forges an export or discovery payload, or a hostile mirror document names an id, to make the guard act on something it should not | medium | mitigate | The guard executes nothing and publishes nothing; the most it can do is disable a row that the forged payload itself created, because a candidate needs the exact core MQTT device identity of an id this instance holds natively plus a native twin; mirror ids reach the manager only through `parse_document`; no new topic is read or written, so the broker ACL is unchanged |
| T-08-50 | Denial of service | A registry listener on every instance runs for every registry change | low | mitigate | The listener returns at once unless the action is `create`, then at once unless the entry is a core MQTT row or a mqtt_actions switch or select whose unique id is a guarded id; it takes no lock; the pass is one synchronous registry call scheduled on the next loop iteration; it is cancelled in `async_stop` (test: no listener after unload) |
