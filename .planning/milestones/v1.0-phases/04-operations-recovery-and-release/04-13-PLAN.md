## Phase Goal

**As a** user running several HA instances, **I want** to re-trigger actions, see who is connected and recover devices, **so that** I can operate the setup with confidence.

This plan's slice: confidence through documentation. Everything the operations tools do, and everything that can go wrong with them, is written down where a user finds it, and tests keep it true.

## Assumptions and defaults (visible, not silent; none are locked decisions, confirm at review)

- **Language:** English, like the README. The integration's own strings are the translations; the docs are not translated.
- **Reconciling the `device_id` rule (post-research decision):** the service field is called `device_id` and holds an instance-specific Home Assistant device id. The existing test keeps README.md and docs/broker-acl.md free of `device_id` in any fenced block. For the new pages a fenced example may contain `device_id` only as a key of the `data` of an `mqtt_actions.<service>` call (YAML parsed, not text matched), never under `target` and never inside actions of a device, and the page must say next to it that the value differs between instances and must not be used in actions that are shared. Responses are documented with the key `uuid`, and the wire payloads in tables, never as fenced JSON with `device_id`.
- **Numbers on the pages** (30 seconds heartbeat, 90 seconds offline, 5 second acknowledgement window, 5 second device interval, 128 remembered request ids, 60 second freshness, 100 imported devices, 4 MiB import size, 8 transfer entries, 5 second resync cooldown) are written next to their constant names and checked against `const.py`.
- **Release documentation:** the README says that `vX.Y.Z` tags create releases, that the tag must equal `manifest.json` `version`, which jobs gate it, that prerelease tags carry a hyphen suffix, and that no zip is built. The first real release is an end-of-phase manual check (plan 04-01).
- **Upgrade notes:** the one-time lapse of approvals (plan 04-02) is documented on the operations page and in the troubleshooting page.
- **No SPEC.md exists; the spec-less probe was skipped.** The prohibitions above were authored by the planner from RESEARCH (Validation Architecture, OPS-05 row) and CONTEXT D-18.
