- Cause, read from `manager.py` (`_sync_export_guard`, `_export_guard_ids`): the guard arms only when this instance's own export is on with the prefix core MQTT listens to, and it acts on this instance's owned devices only. ha-b does not export; its core MQTT receives ha-a's retained export from the shared broker, restores ha-b's own null tombstones as enabled rows, and ha-b's guard is not armed. The README promise (one disabled mqtt row per exported id on every instance) is not met on receivers; the Gaps truth of test 4 already says "on every instance that listens".
- Impact: duplicate entities, possible wrong-entity automations and double triggering on receiver instances after a migration; it reappears at every restart while the exporter keeps its retained export.
