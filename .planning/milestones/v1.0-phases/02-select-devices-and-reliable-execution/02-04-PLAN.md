## Phase Goal

**As a** Home Assistant user, **I want to** create Select devices whose options each run their own actions, **so that** multi-state MQTT devices drive my setup predictably.

This plan's slice: loop protection. An action that changes its own device would otherwise loop forever; the per-device circuit breaker stops it and tells the user why.

<objective>
Add a pure sliding-window `CircuitBreaker`, count real runs per device in the manager, pause the device on a trip (baseline only, runs stopped, Repairs issue and log warning), persist the tripped state across restarts, and define the release paths.

Purpose: STA-06. Retained messages, run modes and buttons make state changes cheap to cause; a device whose actions toggle it back is the classic self-triggering loop. Without a stop, the queue bound (plan 02-02) only limits a burst, not a sustained loop.

Output: `breaker.py`, trip and release handling in `manager.py`, `release_all_breakers` wired into `async_unload_entry`, the issue strings in both languages, and tests for every path. Implements D-14, D-15, D-16, D-17.
</objective>

## Assumptions carried from RESEARCH.md (visible, not silent)

- **A2** The test button stays usable while a device is paused (the test path does not consult the breaker) and test presses are never counted. Pinned by a test.
- **A3** On a trip the running and queued runs of the device are stopped (`Script.async_stop`). Risk if wrong: in-flight sequences would finish and a loop could emit a few more state messages, bounded by the queue of 10. D-15 only says "no actions run" for incoming changes; stopping in-flight runs is the design choice that actually breaks the loop.
- **A8** The additive `tripped` store key needs no `STORE_VERSION` bump; the tolerant loader drops malformed values.
- **A12** Release works through a changed device configuration or an unload or reload of the entry, not through a flow hook. A save that changes nothing does not release, because `async_update_subentry` is then a no-op and no reconcile runs; the Repairs text and the README say "change the device or reload the integration". `Manager.async_stop` itself must not release, because `__init__.py` also calls it when a setup fails and Home Assistant shutdown never calls the unload (so a plain restart keeps the tripped state, D-17, while a user reload releases it, D-15).
- **A7** Breaker inputs are limited to 1..100 runs and 1..3600 seconds; the flow (plan 02-05) enforces the ranges, the model loader already falls back to the defaults for invalid stored values.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| State topic to breaker | A party with write access, or the device's own actions, can generate an unbounded stream of changes |
| Store on disk to Manager | The persisted tripped map is read back at start and decides whether a device may run |
| Repairs and log output | Text shown to the user must not carry action data |
