This plan's slice: prove the phase as a whole and tell the truth about it. A real broker enforces the documented ACL, three instances behave as the success criteria say, and the README describes the trust model and its limits.

## Assumptions and defaults (visible, not silent; none are locked decisions, confirm at review)

- **Open Question 1 default:** the generic Home Assistant subentry delete dialog cannot be vetoed and deletes everywhere; the README says so and a manual UAT row checks it.
- **Open Question 6 default:** no hub-level opt-in switch. The README trust section states that per-device, per-instance approval is the opt-in, which reconciles the wording "local opt-in flag" in `.claude/CLAUDE.md`; that file is project guidance and is not edited by this plan, and the planning return flags the wording to the user.
- **A12:** a denied QoS 1 publish under a Mosquitto ACL is not assumed to fail visibly; the ACL tests tolerate a missing acknowledgement and assert on what a reader receives.
- **Accepted and documented risks (not solved):** forged tombstones force re-approval (D-09, A10); a foreign write that predates the owner's start is only caught best-effort; changing the MQTT discovery prefix at runtime needs a reload; healing recreates mirrored entities and loses their user customizations (A8); residual step kinds (local scripts and automations, scenes, device actions, events) are outside the denylist; actions are readable on the broker.
- **Self-derived edge cases (no SPEC.md exists, the spec-less probe was not run):** the prohibitions above and the scenario list were authored by the planner from RESEARCH and CONTEXT.
- **Seam-fix scope:** if a scenario exposes a defect in `sync.py` or `manager.py`, the fix is made here, the failing scenario is the regression test, and the SUMMARY names the defect and the earlier plan it belongs to.
