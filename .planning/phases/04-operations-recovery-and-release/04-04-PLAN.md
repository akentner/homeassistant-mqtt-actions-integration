## Phase Goal

**As a** user running several HA instances, **I want** to re-trigger actions, see who is connected and recover devices, **so that** I can operate the setup with confidence.

This plan's slice: the first things a user sees. The integration page gets a hub device with the roster of connected instances and a button that republishes everything this instance owns.

Output: `entities.py`, `sensor.py`, `button.py`, platform forwarding in `__init__.py`, `Manager.async_resync`, entity translations in English and German and the tests. Implements D-06, D-12 and the hub part of D-13.
</objective>

## Assumptions and defaults (visible, not silent; none are locked decisions, confirm at review)

- **Roster state counts this instance** (assumption A10 of the research): a lone instance shows 1. The attribute list contains this instance too, first.
- **Attribute content:** full instance ids in the sensor attributes (they help to write the ACL, and D-17 shortens ids only in diagnostics); names come from validated heartbeats.
- **Resync cooldown:** `RESYNC_MIN_INTERVAL_SECONDS = 5.0` in `const.py`, measured on `Manager.clock`. `Manager.async_resync()` returns False when throttled or when the manager is not running, and True after it republished. The button ignores a throttled press quietly (debug log); the service of plan 04-08 raises a translated error.
- **Resync also publishes a heartbeat** because it reuses `_async_republish`; the heartbeat is not retained, so the documented order of the retained topics (documents, discovery, `online`) is unchanged (D-12).
- **Hub device identity:** identifiers `(mqtt_actions, <config entry id>)`, so it survives a change of the instance id (plan 04-12); device type `service`; manufacturer `MQTT Actions`; model `Hub`.
- **Platform order:** only `sensor` in Task 1, `button` is added in Task 3; later plans add `select`.
- **No SPEC.md exists; the spec-less probe was skipped.** The prohibitions above were authored by the planner from RESEARCH Patterns 5 and 11.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Broker to sensor attributes | Instance names and versions of peers reach the state machine |
| User to resync | Any Home Assistant user can press a button entity |
| Entity platform to manager | Platform setup runs against a running manager |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-15 | Denial of service | resync pressed or automated in a loop | medium | mitigate | `RESYNC_MIN_INTERVAL_SECONDS` cooldown on `Manager.clock`, and `_async_republish` takes the manager lock, so work cannot queue unbounded (`test_resync_is_throttled`) |
| T-04-16 | Denial of service | roster attribute above the recorder limit breaks state writes | medium | mitigate | The attribute is unrecorded and capped at the tracked-instance cap plus this instance (`test_roster_attribute_is_unrecorded_and_capped`) |
| T-04-17 | Tampering | a user without admin rights presses resync | low | accept | The press only republishes what this instance already owns, idempotently and throttled; the admin-only service of plan 04-08 is the scripted path |
| T-04-18 | Spoofing | forged peer name shown in the sensor | low | accept | Names come from heartbeats validated for printable text and length; the roster is advisory and the ACL binds each instance to its own heartbeat topic |
| T-04-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs nothing |
</threat_model>
