## Phase Goal

The Phase 5 UAT debt is closed on real instances (ROADMAP Phase 8, success criterion 4, second clause): with the Discovery export on the core MQTT prefix, every instance yields only disabled duplicates. Plan 08-04 recorded that clause as FAILED for Lampe Test and Bar Select on both instances (enabled `mqtt` rows `switch.lampe_test_2`, `select.bar_select_2`); the owner left it open as a gap (UAT04-DISPOSITION leave-as-gap, 2026-10-08), and the verification report (`08-VERIFICATION.md`, gaps entry) asks for an isolated reproduction, a decision between product gap and bench artifact, and a re-run.

<objective>
Reproduce UAT-04 clause 2 in isolation on the live bench, classify the cause from observed values, and obtain the owner's decision on how the gap is handled.

Purpose: the cause is an inference so far (core restores `disabled_by` from a deleted-entity tombstone that the UAT-02 legacy replay left behind). Nobody can decide between a product gap and a bench artifact on an inference. This plan turns it into observed values with a controlled pair of fresh devices (one without and one with a real tombstone), exported in the same window, and puts the evidence in front of the owner together with what each way of closing the gap costs.

Output: the `uat-04-isolation` evidence, the classification, the owner decision recorded under `UAT04-GAP-DISPOSITION`, an updated root cause in the Gaps entry, and the bench back at its baseline. No product, test, workflow or manifest file changes in this plan.
</objective>

Execution rules for the whole gap closure (they repeat the rules of plan 08-01 and add what this gap needs):

- **Run in the main checkout, not in an isolated worktree.** The containers bind-mount `custom_components/mqtt_actions` of the main checkout read-only and the bench is one shared mutable thing. Do not switch branches, rebase or reset. The plans 08-11 to 08-14 are strictly sequential (waves 11 to 14).
- **A failed check is a recorded result, not a stop (D-08).** A check script ends in PASS, FAIL or ABORT. ABORT means the bench was wrong: fix the bench and re-run, never record it. In this plan the isolation script exits 0 for any valid classification, because a reproduced defect is the expected evidence here and not an abort; it exits 2 (ABORT) for a bench problem.
- **Every API call goes through `~/ha-test/bin/ha-test-guard`** (never `ha-ws`, never the `ha` wrapper, never production). Never read `.storage/auth`, never dump `core.config_entries`; read single non-secret fields with `jq` and project registry files to the fixed fields named in the tasks.

## Fixture facts (verified 2026-10-08; re-read before relying)

- Core MQTT restore: HA 2026.9.4 `homeassistant/helpers/entity_registry.py` lines 1498-1508 pop the deleted entity with the same (domain, platform, unique id) and, when its `disabled_by` is not UNDEFINED, copy it onto the new row; a tombstone with `disabled_by` null therefore overrides `enabled_by_default` false. Tombstones whose `orphaned_timestamp` is null are never purged (`async_purge_expired_orphaned_entities` skips them), so the condition is permanent, not transient.
- Tombstones on the bench now (read from both `core.entity_registry` files): platform mqtt, switch unique id of Lampe Test and select unique id of Bar Select with `disabled_by` null on ha-a and on ha-b, four `_test_` button tombstones with null, and the UAT Marker switch with `disabled_by` integration (it never had an enabled duplicate; its tombstone came from the removal of the disabled row in plan 08-04). Fresh uuids appear nowhere in these files.
- The replay catch (`takeover.remove_replay_twins`) selects by the core MQTT device identifier (`mqtt`, `mqtt_actions_{device id}`), platform, domain and unique id, not by topic prefix; it removes core-prefix export duplicates as well, and `async_remove` stores the removed row's `disabled_by` in the new tombstone. An enabled legacy twin therefore leaves a tombstone with null, which is the field path the isolation reproduces.
- README section "MQTT Discovery export" says the core-prefix duplicates "are disabled by default"; `tests/test_docs.py::test_readme_documents_the_discovery_export` pins a sentence that contains both "duplicate" and "disabled by default". The unit test `test_the_export_on_the_core_prefix_creates_a_disabled_duplicate` covers only the fresh-id case.
- Archived verification digests: `README.md`, `custom_components/mqtt_actions/discovery.py` and `manager.py` are in the `covered_files` of the archived Phase 1 to 4 reports, `takeover.py` in Phases 3 and 4, `docs/troubleshooting.md` in Phase 4, `08-UAT.md` in Phases 1 to 3. Any edit to those files stales the digest of the reports that cover them (this is what the options of Task 3 cost).
- Bench: ha-a and ha-b run HA 2026.9.4 at the pinned build `b7f52b34a1e8d6afbf6e1ac75f3b92bbbe54a8f3`, `mosq` runs and is never restarted, ha-c is stopped, the stale anchor is empty, the hub options of ha-a read `discovery_export` false and `export_prefix` `mqtt_actions_export`, the ACL rows for `mqtt_actions_export/#` exist for `ha_one` and `ha_two`.
