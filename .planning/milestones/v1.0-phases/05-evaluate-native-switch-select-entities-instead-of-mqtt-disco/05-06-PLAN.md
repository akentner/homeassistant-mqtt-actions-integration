## Phase Goal

Existing installations migrate automatically and a mixed fleet keeps working throughout: the owner switches to native entities only once all online peers are capable. This plan builds that decision, the capability signal it reads and the hint that explains a wait.

<objective>
Add the heartbeat capability, the roster gate, the settle timer and the cutover check that flips an instance to native, with a Repairs hint for the peers that block it (D-09, D-10, D-12, MIG-02).

Purpose: D-06 asked that older instances be told. D-09 realized it without a schema bump: the new instance never switches under a legacy peer that is online, and says why when it waits. The rest of the fleet needs no coordination beyond one additive heartbeat key.

Output: capability and blocking logic in `presence.py`, the cutover state machine in `manager.py`, the hint issue with en and de strings and a troubleshooting entry, the test fixtures that keep the legacy suite legacy, and `tests/test_cutover.py`.
</objective>

## Assumptions and defaults (visible, not silent; none are locked decisions)

- **Settle time 5 seconds:** `CUTOVER_SETTLE_SECONDS` is 5.0, the order of magnitude of core MQTT's own discovery cool-down. It only has to cover the retained availability replay at subscribe; the capability itself is read from heartbeats (every 30 seconds), and an announced-online instance without a heartbeat blocks until it was silent for 90 seconds.
- **The capability key is the marker key of plan 05-04:** the heartbeat carries `entities: native` (`NATIVE_KEY` and `NATIVE_VALUE` of `document.py`), always, because it describes what the build can do and not what the instance already did. A v0.1.0 heartbeat has no such key, which is how it is told apart; version strings are never compared (prerelease tags exist).
- **A new device does not wait:** once the instance flag is set, a device created later is native at creation and not pending; while the instance waits, a new device is legacy and part of the pending set at the cutover.
- **No reload without devices:** an instance with no owned device sets its flag without a reload, because nothing needs a takeover; its mirrors flip through the markers of their owners (plan 05-07).
- **The hint is a plain warning issue, not fixable:** it is created while the gate holds, names at most `CUTOVER_HINT_MAX_NAMES` peers with escaped names, and is deleted when the cutover proceeds or no peer blocks. D-09 forbids a hint on the legacy instance; this one is on the new instance.
- **Test default:** an autouse fixture sets the manager's `CUTOVER_SETTLE_SECONDS` to None for the whole suite, so no timer is armed and every Phase 1 to 4 test and every earlier test of this phase keeps the legacy path it asserts; `enable_native_cutover` restores the real value for the tests of this plan and plan 05-07.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Heartbeat and availability messages to the gate | Anyone on the broker can publish a heartbeat or an availability message under an instance id |
| Broker-supplied peer names to the Repairs text | Names reach a Repairs issue, which renders markdown |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-5-04 | Tampering | A forged heartbeat capability makes a legacy peer look native, or a forged legacy heartbeat keeps the owner from switching | low | accept | The gate only decides when a UI change happens: a forged capability can make a legacy instance lose UI entities (never actions), a forged blocker only delays the switch and is shown in the hint; heartbeats are already validated, size-capped and tracked with a roster cap (T-04-09 to T-04-12), and the broker trust model is documented as cooperative |
| T-5-13 | Denial of service | The cutover flips repeatedly or reloads in a loop | medium | mitigate | The flag is persisted before the reload and the check returns when it is set; the settle timer is armed only while it is not set; `test_the_cutover_runs_once` |
| T-5-14 | Tampering | A broker-supplied peer name injects markup or a log line through the hint | low | mitigate | Names pass `escape_markdown`, are capped in number, and are never written to a log |
| T-5-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs nothing |
</threat_model>
