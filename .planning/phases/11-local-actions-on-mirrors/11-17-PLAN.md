<objective>
Close gap G-04 (ledger finding F-04). `_async_drop_mirror` pops `_tripped` and deletes the breaker issue, and the main Store is then saved without the trip. If the subentry creation fails, the rollback restores approval, the native flag, the records and the mirror, but not the trip. The restored mirror runs owner and local actions again, although no release happened.

Purpose: MIR-09 and Phase 2 D-17 say that only a local edit, a changed owner document or a reload releases a breaker. A failed adoption is none of these (T-11-17, T-11-15).
Output: the rollback restores and saves the tripped hash, a regression test pins it, ledger row F-04 is FIXED, and the ledger has no OPEN or ROUTED row left.

One deviation from the ledger wording, with the reason: the ledger proposes saving the trip "before the mirror is restored". This plan saves right after `sync.async_restore_mirror`. At start, `_tripped` is kept only for ids among the restored mirrors (manager.py:956). A save made before the restore lacks the mirror payload, so a stop before the delayed mirror save would drop the trip. The hash itself is still put back before the restore, which `_restore_tripped` needs.
</objective>
