<objective>
Fix review finding WR-06, recorded in 11-VERIFICATION.md as `coincidental_reliance_items[0]` and as a human-decision item. The owner decided on 2026-10-21 to fix it in a gap plan.

`async_set_local_action` clears `local_action_failed` right after the durable commit of a record without local actions (11-19). A run of that trigger that is still in flight keeps going. The rebuild cancels it, and the runner's `finally` then delivers a FAILURE outcome. `async_report_local_outcome` drops a failure only when the record is gone, not when it has no actions. So the issue comes back, naming a trigger that has no local actions. The reviewer's probe reproduced it: the issue was absent right after the mute save and present after settling. The only ways out were saving the mute again or removing the customization, and removing it brings back the owner actions the user had suppressed.

Purpose: the promise "saving that trigger without local actions ... ends it" (README, troubleshooting, D-19 as amended) holds for a run in flight too.
Output: a one-condition guard, a probe-based regression test for both "without local actions" saves, a direct-outcome test, a bound test that keeps real failures, and disposition row WR-06 = fixed.
</objective>
