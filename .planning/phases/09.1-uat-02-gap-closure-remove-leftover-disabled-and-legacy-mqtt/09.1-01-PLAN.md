## Phase Goal

A retained legacy Discovery replay at start leaves no disabled or legacy mqtt rows and no legacy device behind, from integration and from null tombstones, without ever clearing another instance's export (CR-01). UAT-02 (both tombstone states) and UAT-04 then pass on the bench on exactly the fix SHA, which plans 09-04 and 09-05 tag and release as v1.0.1 (REL-01).

<objective>
Fix the root cause found by research for the legacy-payload case, test first. The duplicate guard disables the replayed switch or select about five seconds before the quiet-period catch, and the catch skips every disabled row (CR-01). This plan teaches the catch what is retained on the core-prefix discovery topic and lets it remove the twin the integration disabled when that content is the legacy payload. The owner then clears the stale legacy topic, and a follower publishes nothing.

Purpose: this closes E1 to E3 of UAT-02 for the bench rounds, where the retained legacy payload is on the topic at start. The empty-topic case (the heal start, and export rows after "export off") follows in plan 09.1-02.

Output: `DiscoveryContent` and `classify_discovery` in `discovery.py`, the verdict map in `sync.py`, the refined `remove_replay_twins`, the catch and the owner clear in `manager.py`, the regression and guard tests, and the bench fingerprint `heal-start/bench-before-fix.txt`.
</objective>

## Decisions this plan implements (visible, not silent)

- **D-01, D-02, D-03, D-04:** a disabled replay twin is removed only when `disabled_by` is `integration` and the content of the core-prefix topic is LEGACY or EMPTY. EXPORT and UNKNOWN keep it. The customization, twin and identity rules of `remove_replay_twins` stay byte-identical. EMPTY is recorded here only from a live empty message that the subscription saw. Inferring EMPTY for a topic without any message needs the settle signal of plan 09.1-02.
- **D-05:** RED first. The new regression test starts from integration tombstones and from null tombstones. The existing null-tombstone tests keep their assertions. The CR-01 unit test of `remove_replay_twins` (`tests/test_takeover.py`) stays byte-identical, because the default content keeps CR-01.
- **D-06 plus user decision 4:** the owner clears whenever the content is LEGACY, the device is in `devices`, not in `sync.transferred_away`, and `takeover.legacy_device(...)` is None after the catch, even if this run removed nothing. The clear runs after the registry flush, through `DiscoveryPublisher.async_clear_device` wrapped in `_async_attempt`, like the takeover clear.
- **D-08:** a legacy device that keeps a row stays, and then the owner does not clear.
- **D-09 (guard):** Task 1 records the container StartedAt and the leftover projection before the first product edit, so plan 09.1-05 can prove that no intermediate tree ever started.
- **Research mechanism, not the CONTEXT hypothesis:** the rows come back ENABLED from both tombstone states. Core re-enables an `integration` record, and the registry restores a null record. The guard then disables the switch or select. The tests reproduce exactly that.
- **Planner decisions (Claude's discretion, documented):** (1) The content source is the existing `<prefix>/device/+/config` subscription of `SyncManager` (research Pattern 1, public API). The verdict is an enum, never the payload. (2) A held id is an owned id (from its config subentry, which exists before the owned devices are registered at start, so a retained replay during the start is not lost) or a mirror id. (3) `classify_discovery` returns None for the live migrate payload, which leaves the retained content as it was. (4) The bench's two-round structure is mirrored by two rounds in the regression test. (5) `remove_replay_twins` keeps its keyword-only signature and gains `content` as a keyword with default UNKNOWN, so the takeover-path call and every existing test keep CR-01.
