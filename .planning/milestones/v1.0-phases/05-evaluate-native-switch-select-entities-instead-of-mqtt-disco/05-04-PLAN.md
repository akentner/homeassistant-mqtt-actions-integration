## Phase Goal

Switch and select entities owned by the MQTT Actions config entry replace MQTT Discovery as the default, so every device and entity of every instance, mirrors included, shows on the integration page. This plan makes mirrors native: the document marker that carries the information, the entities it produces and their availability.

<objective>
Add the additive unhashed marker to the config document, give mirrors of marked documents native entities directly under the entry, and keep their availability, lifecycle and one-way status correct (D-07, D-09, ENT-01, ENT-02, MIG-02).

Purpose: the Phase 3 UAT finding that the devices of another instance cannot be found is answered here. The marker is the only thing a follower needs to know, and it must be safe to ignore for every v0.1.0 instance.

Output: marker support in `document.py`, `MirrorInfo.native` and `is_native` for mirrors, the owner marker in the device info, the availability signal in `sync.py` and the tests.
</objective>

## Assumptions and defaults (visible, not silent; none are locked decisions)

- **Marker shape:** the key `entities` with the string value `native`, written next to `transferred_from` at the top level of the document, outside the shared content. Any other value, type or absence reads as not native; the parser never rejects a document because of it, so a future value cannot break this reader (V5, T-5-03).
- **The owner writes the marker in plan 05-05 and 05-06**; this plan only builds and reads it. The tests build marked documents with the helper.
- **Mirror device marking (D-07):** the owner is named in the model text, `Switch device (mirror of <owner name>)`, which is plain text bounded by the parser's limits (T-5-05). A legacy mirror keeps `(mirror)` unchanged.
- **Native-ness is one-way per mirror:** once a mirror is native it stays native when a later document of the same owner lacks the marker; the document of a competing owner is the existing owner conflict and changes nothing. Adoption rules follow in plan 05-05.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Foreign document to the mirror's native status | A document claims "native", which decides whether this instance shows legacy or native entities for the device |
| Owner announcement to entity availability | The availability topic decides whether the user can command a mirror |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-5-03 | Tampering | A forged marker in a document claims "native" and makes followers switch their entities | medium | mitigate | The marker is honored only from the owner the mirror is pinned to (the existing first-owner-wins rule); a competing owner's document is the owner conflict and changes nothing; the worst case is a UI change on that mirror, never action execution, because approval and the Script gate are untouched; `test_a_marker_of_a_competing_owner_changes_nothing` |
| T-5-11 | Tampering | A document without the marker, or an old instance, pushes a native mirror back to legacy and creates duplicate entities | medium | mitigate | Native-ness is one-way per mirror: replacing a mirror record keeps native; `test_an_unmarked_document_never_reverts_a_native_mirror` |
| T-5-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs nothing |
</threat_model>
