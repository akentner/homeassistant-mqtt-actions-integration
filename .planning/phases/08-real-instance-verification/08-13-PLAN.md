## Phase Goal

UAT-04 is run again on the state the owner's decision prescribes, with the original expectations, and the observed result is kept as evidence beside the first failing run (ROADMAP Phase 8, success criterion 4).

<objective>
Prepare the bench for the re-run (script patches, then a tombstone prune or a build re-pin) and run the checks the disposition requires, writing evidence only.

Purpose: the gap closes only through a recorded run, never through an edit of the record. This plan produces the run and its evidence; plan 08-14 records the outcome in the ledger and the traceability. The first failing run stays as history.

Output: `uat-04-rerun` evidence (and `uat-02-rerun`, with `uat-03-rerun` and `p1-5-rerun` for the full re-run of a guard build), the prepared bench state, patched and new bench scripts with scrubbed copies.
</objective>

## Applicability

The plan applies for all four dispositions; the work differs. Run `~/ha-test/bin/check-uat04-iso.sh disposition` first: a missing or invalid disposition (exit 2) FAILS this plan, it never means "skip". Then read the `applies` targets prune (document, bench-artifact), repin and guard (guard, guard-and-document), full-rerun and scoped (the modifier of a guard option). A target that prints no is not run and is recorded as `not selected` in the SUMMARY.

## Decisions this plan implements (visible, not silent)

- **D-01:** only ha-a, ha-b and `mosq`; production untouched.
- **D-03:** a changed build is re-pinned and the checks the owner confirmed as affected are re-run; the stale anchor is read against the pinned sha.
- **D-04:** the prune, the re-pin and the runs are scripted; no owner step.
- **D-07:** nothing is overridden; a FAIL stays a FAIL unless the owner records an override in their own name.
- **D-08 (failure rule, which stands):** a failed check is a result and is never turned into a pass; the placement clause of D-08 was waived for this gap closure (D08-WAIVER, recorded by plan 08-12 Task 1).
- **Planner decisions (documented, not owner choices):** (1) the first failing evidence stays in `uat-04`; the re-run uses the environment variable `PHASE8_EV_SUFFIX` (value `-rerun`) to write beside it, which needs a one-line change per check script and leaves every expectation untouched, shown by a diff; (2) the ACL backup `acl.bak-phase8-04` of the first run is the pre-edit copy the ledger names, so the re-run must not overwrite it; (3) the nested gate `check-uat02.sh clean` inside `check-uat04.sh run` reads the baselines of the recorded run, so it runs with the suffix variable unset; (4) pruning the mqtt tombstones by editing the stopped registry files is acceptable on the test bench only, with copies first and checks before the start; it is what the verification report calls a clean state, and the pass it allows is recorded by plan 08-14 with the qualifier that it holds only on a pruned state.
