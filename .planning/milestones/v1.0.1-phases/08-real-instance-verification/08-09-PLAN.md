## Phase Goal

The two Phase 1 items that need a real host run there: the HACS client install (P1-1) and the core version of the second real host (P1-6) (ROADMAP Phase 8 success criterion 6; decision D-02).

<objective>
Get the owner's choice of production host and install path, let the owner perform P1-1 and P1-6 (add and remove only, no device created, own base topic), and record both results with evidence.

Output: blocks 5 and 10 recorded, `p1-1` and `p1-6` evidence, the residue decision recorded.
</objective>

## Decisions this plan implements (visible, not silent)

- **D-02:** P1-1 runs on one production host (HACS client, add and remove only, no device created) and P1-6 is read by the owner in Settings > About. These are the only production touches in the phase.
- **D-04:** everything that needs no human is automated: the release identity check against the public repository, the evidence scan, the ledger. The owner performs only the client and host steps.
- **D-07, D-08:** both items are in scope, none waived by default; a failure or rejection is `result: issue` with a Gaps entry; an abbreviated P1-1 is an override under the owner's own name.
- **Planner decisions (documented):** (1) the temporary hub is set up with the base topic `phase8_hacs_check` and the instance name `phase8-hacs-check`, so it mirrors no production device, raises no approval request and publishes only under its own topic (the base topic is chosen at setup and cannot be changed later); (2) Claude gives the owner a read and a clear command for the one retained availability topic the temporary instance leaves behind, but does not run it (D-01); (3) hosts appear in committed evidence by role ("production host 1"), never by name or address.
