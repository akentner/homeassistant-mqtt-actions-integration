## Phase Goal

The info findings of both Phase 8 reviews are closed, and the takeover, replay-catch and duplicate-guard orchestration lives in its own module, so `manager.py` is smaller and quiet before MIR-01 edits it (FIX-01 to FIX-08).

<objective>
Close review 2 IN-02 (FIX-07): the no-clear guarantee for loaded rows no longer depends silently on the Home Assistant internal eager task in `Entity._async_registry_updated`; a loud test pins it at both call sites (D-07, D-08).

Purpose: `takeover.remove_replay_twins` disables an enabled, loaded core MQTT row and removes it in one synchronous step. Core publishes no clear only because the eager task unsubscribes the entity before the remove event. If core drops `eager_start`, core's clear-on-remove would empty a topic every instance shares, and only a behavioral test catches it (research Pitfall 9). One function-level test pins it today; these pins cover the start-up takeover path and the replay catch through the manager.

Output: two pins and their hint in `tests/test_core_contracts.py`.
</objective>
