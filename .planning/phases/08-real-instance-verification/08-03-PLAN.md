## Decisions this plan implements (visible, not silent)

- **D-01:** ha-a, ha-b and `mosq`; production untouched.
- **D-03:** each task starts with `check-preflight.sh --quick`; a restart in P1-5 re-uses the same mounted files, so the SHA stays valid and is asserted again at the end.
- **D-04:** commands, publishes, restarts, reloads and log evaluation are scripted. The unapproved control and the approval step use the Repairs API when it behaves as assumed (research A5), else the browser MCP, else a `checkpoint:human-action` (fallback rule).
- **D-08:** FAIL becomes `result: issue` plus a Gaps entry; the next check still runs.
- **Planner decisions (documented, not owner choices):** (1) the marker device is created through the documented `import_devices` service because it is scriptable and creates an owned device with a new uuid (a device created by hand in the UI would need the owner for every re-run); (2) the marker's actions are inert (`system_log.write` only), so importing them is safe on the test bench; (3) the "UI toggle" of P1-5 is the `switch.turn_on` or `switch.turn_off` service call, which is exactly what the frontend toggle calls; the rendering is not what P1-5 judges.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| imported action content to the owning instance | An import creates an owned device whose actions run without approval on ha-a |
| external publisher to the state topic | Anyone with the state-topic ACL can trigger actions on every approving instance |
| shared retained state topic | A retained unknown payload would overwrite the broker's last good state |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-08-09 | Tampering | An unknown payload published retained would poison the retained state of the marker | medium | mitigate | The `banana` publish is not retained (checked in the topic capture: retain flag 0) and the retained value is read back unchanged afterwards |

| T-08-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs no package |
