A retained legacy Discovery replay at start leaves no disabled or legacy mqtt rows and no legacy device behind, from integration and from null tombstones, without ever clearing another instance's export (CR-01). UAT-02 (both tombstone states) and UAT-04 then pass on the bench on exactly the fix SHA, which plans 09-04 and 09-05 tag and release as v1.0.1 (REL-01).

## Decisions this plan implements (visible, not silent)

- **D-02 (empty clause) and user decision 2:** a settled empty topic makes an `integration`-disabled twin a candidate, export rows after "export off" included. G6 (`tests/test_export_guard_receiver.py`) is rewritten to that rule. The shipped README and troubleshooting text already promise that "the next start removes them".
- **D-03:** "not delivered yet" is UNKNOWN. EMPTY needs all of three things. First, the settle signal through the public `mqtt.async_on_subscribe_done`, called only inside `mqtt_gateway.py` per the project rule. Second, a grace of `DISCOVERY_SETTLE_GRACE_SECONDS` on the manager clock after the settle (research A2: retained messages follow the SUBACK). Third, the id was held when the subscription was made. A mirror created later in the run has had its retained message dropped, so it reads UNKNOWN until a message arrives. A discovery qos other than 1 means the settle never matches, and EMPTY is never inferred (safe direction). `on_reconnect` resets the settle and the scope. The INFO line carries a count only.
- **User decision 5:** no migrate-before-clear. The cross-instance effect goes into `docs/troubleshooting.md` here. The release notes follow in plan 09.1-06.
- **Research A1:** pinned on the broker tier with real Mosquitto, because the CR-01 safety of the EXPORT verdict depends on the sync subscription receiving the retained replay.
- **Planner decisions (Claude's discretion, documented):** (1) The grace constant lives in `sync.py`, like `REPLAY_QUIET_SECONDS` in `takeover.py`, and is read at call time, so fixtures can patch it. (2) Test determinism follows the conftest precedent of `disable_native_cutover` and `enable_native_cutover`. An autouse fixture sets the grace to infinity, so no PHACC test ever infers EMPTY by timing chance. The opt-in fixture `discovery_settled` sets it to 0 and makes the gateway's settle callback run at once (research Pitfall 2). Both fixtures patch with `raising=False`, so the RED run fails on an assertion, not on a missing attribute. (3) Multi-instance test T15 is not planned. FakeBroker instances have no core MQTT discovery rows, so the catch has nothing to remove, and the follower rule is covered by the PHACC test of plan 09.1-01 (research marked T15 optional). (4) The scope is a snapshot of the mirror ids at subscribe time. An owned id is judged by its subentry, which the owner configured and the broker cannot create.

## Flagged assumptions (spec-less fallback, never silently dropped)

- **Spec-less probe fallback skipped: the phase has no requirement IDs to probe (visible skip).** The prohibitions are plan-authored from CONTEXT D-01, D-03, D-13 and D-14.
- Research A3 (nothing publishes a non-retained empty payload over a retained export) is accepted as stated. A seen empty message counts as EMPTY, because a retained clear reaches established subscriptions as a live empty message.
- The narrow race of research Pitfall 3 (a foreign export republished between this instance's decision and the clear by its core, for example right after a broker restart without persistence) is an accepted residual risk (user decision 2). Plan 09.1-06 records it in PROJECT.md and the release notes.
