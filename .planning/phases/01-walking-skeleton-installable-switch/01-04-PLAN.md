## Phase Goal

**As a** Home Assistant user, **I want to** create a Switch device whose MQTT state changes run my configured actions, **so that** I need no YAML automation.

This plan's slice: the trigger path. Which messages count as a change, what survives a restart, and what the user sees when an action fails.

<objective>
Complete the decision function and its tracker, persist the per-device baseline, and make action failures visible (log plus one Repairs issue per device) with serialised runs.

Purpose: the core value is "a state change reliably triggers actions", and the core risk is the opposite failure: an action storm on restart from retained messages, or a silent failure that looks like success. STA-04, STA-05 and DEV-08 make both cases testable.

Output: complete `state.py`, Store persistence in `manager.py`, FIFO runs and Repairs surfacing in `runner.py`, unit and integration tests, and a real-Mosquitto test that pins the retain-flag invariant the whole baseline strategy rests on. Implements D-02, D-05, D-06, D-07, D-08, D-09, D-14.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MQTT broker to StateTracker | Payload text and the retain flag come from a party with broker write access |
| ActionRunner to HA logs and Repairs UI | Error text can echo rendered templates and service data |
| Store on disk | Baseline map persists across restarts |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-10 | Information disclosure | Repairs issue text and log lines from failed runs | medium | mitigate | Error text capped at MAX_ISSUE_ERROR_LENGTH; only device name, trigger name and exception are logged, never the action data; a canary test proves it |
| T-01-11 | Denial of service | rapid alternating payloads and unknown-payload log lines | medium | accept | The per-device FIFO keeps runs ordered but unbounded; the circuit breaker and queue bounds are STA-06 in Phase 2; unknown-payload log lines carry a truncated repr so a payload cannot inject newlines or grow a line |
| T-01-12 | Tampering | retained replay causing an action storm at restart or reconnect | high | mitigate | Retained messages are baseline-only (STA-04); last_acted is persisted (STA-05); the run-on-startup flag is opt-in per device and fires once only; the broker test pins the retain-flag semantics this depends on |
| T-01-SC | Tampering | package installs | low | accept | This plan installs nothing; the broker test uses the paho client already provided by Home Assistant |
</threat_model>
