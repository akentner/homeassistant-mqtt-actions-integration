## Decisions this plan implements (visible, not silent)

- **D-01:** the warning lists the core MQTT entity ids with a reason, grouped as two placeholders `customized` and `rejected` plus `count`, so the reason labels are translated text and not English inside a placeholder. Entity ids are local registry data; they are still escaped with `escape_markdown` and capped (KEPT_DUPLICATES_MAX_SHOWN = 10 per reason; an em dash for an empty group, the dialog convention of Phase 3).
- **D-02:** one issue id `kept_duplicates` per instance, not in `ISSUE_DEVICE_PREFIXES` (research Pitfall 15 suggested the prefix list; D-02 makes it per instance, so it gets its own constant, and plan 10-10 adds it to the hub-removal set). Non-fixable, never a delete action, no row removed.
- **D-02 and Pitfall 15 (dismissal), Claude's discretion on the mechanism:** the refresh compares the new placeholders with the issue registry's current entry: an active entry with the same placeholders is left alone (a dismissal within a run stays); any difference, or an entry restored inactive after a Home Assistant restart (core keeps no text for a non-persistent issue, so a change cannot be ruled out), is deleted and created again; an empty list deletes it. A dismissed warning therefore comes back once after a Home Assistant restart while duplicates remain; that is the safe side of Pitfall 15.
- **D-03:** only enabled kept duplicates; the D-03 fail-safe twins are disabled and never candidates.
- **D-04:** the three evaluation points; no listener of its own.
- **Planner decision (reason precedence):** a row whose native twin is turned off is reported as `rejected` even when it is also customized, because the guard keeps it for that reason alone.
- **Planner decision (scope):** the candidates are the guard's: the switch or select row of the core MQTT device whose unique id is the device id, enabled, with a native twin under this entry. Test-button rows are out: the guard never acts on them, and a native test button is disabled by default (quick task 261003-rmy), so a "twin turned off" reason would be meaningless for them.
- **Planner decision (no drift):** `disable_duplicates` is refactored onto the shared `_guard_candidates` iterator with unchanged behavior; its existing tests stay green and a partition test pins that the two functions split the candidates.

## Flagged assumptions (edge probe)

- **FIX-08 (unclassified, unresolved, surfaced):** the probe found no edge category. Assumptions: the cap per reason (10) is enough to identify the rows, the count placeholder carries the total; a device another instance adopted (transferred away) is not listed, like the guard; a failure while building the list leaves the current warning as it is until the next evaluation point.
