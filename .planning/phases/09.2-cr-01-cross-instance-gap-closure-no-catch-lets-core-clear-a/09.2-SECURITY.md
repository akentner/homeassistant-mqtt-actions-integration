## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| broker heartbeat topic to this instance | any client on the unauthenticated broker can publish a heartbeat with any `kept_legacy` value | device ids (untrusted input) |
| this instance to the broker heartbeat topic | the kept list leaves the instance on every heartbeat, readable by every client | device ids (low) |
| catch / takeover pass to the shared core-prefix topic | migrate and empty retained payloads reach every instance's core MQTT | discovery payloads (high impact) |
| broker core-prefix topic to the follower's catch | any client can publish an empty or legacy payload on a held device's discovery topic | discovery payloads (untrusted input) |
| documentation to users | users act on the documented keep/cleanup behavior | docs |
| phase branch to local main / local repo to origin | the fix enters the release line and is published by the owner | commits, CI runs |
| repo working tree and backups to the bench containers | ha-a and ha-b run the main checkout; registries restored and reseeded while stopped | registry files |
| Claude to the shared broker and test instances | retained legacy payload and renames for the CR-01 gate (ha-test-guard tokens only) | discovery payload, entity names |
| bench host files / ledger / release notes to the public repository | evidence, ledger and notes are committed and pushed | projections only (no secrets) |
