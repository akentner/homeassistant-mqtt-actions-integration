# Phase 9.2 Plan 03: The owner waits one heartbeat interval for unheard peers, a follower cleans up once the owner cleared, and the docs state the final behavior (Summary)

**FIX candidate: `a4d08950b0e7be8f190adebe32f65b3a3941af99`.** This is the docs commit, and it is the last commit of the phase branch that changes a path outside `.planning/`.

**An owner whose catch is blocked only because an online instance has not been heard since this start now checks again. It waits for the rest of one heartbeat interval plus the expiry margin, and it uses the existing retry counter and bound. When the peer's heartbeat says it keeps nothing, the owner removes the twins and clears the topic in the same run. When the recorded content of a held device turns from LEGACY to EMPTY, a follower's catch arms again after `REPLAY_RETRY_MIN_SECONDS`, within the same bound, and removes the waiting twins and the emptied legacy device without publishing anything. The troubleshooting page and the README now describe this behavior and its limits.**

## Accomplishments

- `presence.py`: `PresenceManager.listening_seconds()` returns the roster's listening time.
- `manager.py`:
  - **D-04 re-arm.**
    - The clear loop of `_async_replay_catch` now reads the content again for each id. It counts as `unheard` every LEGACY id whose `_topic_verdict(...).rearm` is set, which means owned, no local keep, and peers UNHEARD.
    - The peer-blocked INFO line now counts only peers that are `KEPT` or `UNKNOWN`.
  - **`_rearm_or_log_replay_catch(unknown, unheard)`.** This helper builds the waits:
    - the settle wait, when the content is unknown and the settle can still end, with a floor of `REPLAY_RETRY_MIN_SECONDS`;
    - the peer wait `max(HEARTBEAT_INTERVAL_SECONDS + EXPIRY_MARGIN_SECONDS - presence.listening_seconds(), REPLAY_RETRY_MIN_SECONDS)`.

    The longer wait wins. While `_replay_catch_retries < REPLAY_CATCH_RETRIES`, the helper increments the counter, arms the timer and logs one DEBUG line with counts. Once the bound is reached, it logs the existing "is not known" INFO line and the new "was not heard yet" INFO line. Both lines carry counts only. No new constant was added, and `REPLAY_CATCH_RETRIES` is still 5.
  - **D-06 re-arm.**
    - `_replay_catch_armed` is set by `_arm_replay_catch` and cleared by `async_stop`.
    - `@callback on_discovery_emptied(device_id)` arms the catch after `REPLAY_RETRY_MIN_SECONDS`. It does so only if all of these hold:
      - the manager is running;
      - the start-up catch was armed in this run;
      - no catch timer is pending;
      - the id is native;
      - the MQTT entry exists;
      - a legacy MQTT device is still there;
      - the counter is below the bound.

      It never publishes.
- `sync.py`: `_on_discovery_message` reads the previous verdict before it stores the new one. On LEGACY to EMPTY it calls `manager.on_discovery_emptied(device_id)`. This happens before the `if msg.payload: return` early exit, and the heal logic is unchanged.
- `docs/troubleshooting.md`: the three sentences up to "including one that you renamed or customized in another way." are replaced by the six sentences of the plan, verbatim. The paragraph was re-wrapped to 120 characters, with bold spans kept on one line. "The native entity of the device is not affected." and the "What to do" text are unchanged.
- `README.md`: the Limitations section has the mixed-version bullet, placed after the one-way 0.1.x upgrade bullet.
