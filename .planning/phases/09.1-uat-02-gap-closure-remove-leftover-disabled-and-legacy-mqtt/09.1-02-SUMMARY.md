# Phase 9.1 Plan 02: Settled-empty discovery topic, unknown-content log, export guards and docs Summary

**FIX = `681c58793b656b51869906b62f2564829de7a10d`** (the docs commit, the last commit of Phase 9.1 that changes a path outside `.planning/`).

**A discovery topic that holds nothing now counts as EMPTY, but only after three things: the broker acknowledged the sync's wildcard subscription (public `mqtt.async_on_subscribe_done`), a 2 s grace passed on the manager clock, and the id was held when the subscription was made. With that, the bench heal start (live disabled leftovers, nothing retained) is cleaned. Unknown content keeps every disabled twin and is logged as a count. A retained export still always keeps its row (CR-01).**

- `MqttGateway.async_on_subscribed` wraps the public `mqtt.async_on_subscribe_done`. It returns a no-op when MQTT data is not loaded (`KeyError`), so EMPTY is never inferred then. `mqtt_gateway.py` is still the only module that imports the MQTT integration.
- `SyncManager` keeps `_discovery_settled_at` and `_discovery_scope`. `async_start` snapshots the mirror ids and registers the settle watch at qos 1. `on_reconnect` resets both. `discovery_content` returns a recorded verdict first, then EMPTY under the three conditions, then UNKNOWN.

**2. [Harness adjustment] Gateway tests use `freezer` and bounded loop turns**
- **Found during:** Task 2
- **Issue:** `async_fire_time_changed` runs the debouncer's timer handle, but `EnsureJobAfterCooldown._async_timer_reached` compares against the real `loop.time()` and reschedules. Core then subscribes the queued topics (30 core discovery wildcards first) one by one in an eager task that `async_block_till_done` does not wait for.
- **Fix:** `freezer.tick(5 s)` plus `async_fire_time_changed`, then up to 2000 `asyncio.sleep(0)` turns until `mqtt_client_mock.subscribe` saw the watched filter (asserted, so the negative tests cannot pass vacuously), then 50 turns and `async_block_till_done` for the acknowledgement, the dispatcher task and core's `call_soon`. The test ran stable over 3 repeated runs.
- **Commit:** `d9a70a1`

**3. [Plan text] `_falsy_publishes` imported from `tests/test_takeover.py`**
- The plan names `_falsy_publishes(mqtt_mock, legacy.topic)` in the behavior blocks. It lives in `tests/test_takeover.py` and is imported in `tests/test_native_replay.py`. The import of that module changed from one line to a block.
