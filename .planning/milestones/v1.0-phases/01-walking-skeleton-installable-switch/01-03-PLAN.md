## Phase Goal

**As a** Home Assistant user, **I want to** create a Switch device whose MQTT state changes run my configured actions, **so that** I need no YAML automation.

This plan's slice: everything a user touches before a message ever arrives, meaning the hub setup, the Add-switch dialog with its validation and warning, and the English and German UI strings.

<objective>
Widen the tracer's flows into the authoring experience: strict hub validation, the full Switch subentry flow with reconfigure, invalid-action rejection, the instance-local device_id warning-then-confirm, and complete en and de translations with a parity test.

Purpose: FND-03, DEV-01, DEV-02, DEV-05 and FND-04 are user-facing contracts. Input is the only place where bad base topics (which widen a subscription) and bad action sequences (which run with full local privileges) can be stopped cheaply.

Output: hardened `config_flow.py`, pure validators in `topics.py` and `actions.py`, `translations/en.json` and `translations/de.json`, and four test modules. Implements D-01, D-03, D-06, D-10, D-11 and builds on the D-13 go-subentry verdict recorded in 01-02-SUMMARY.md.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin user input to flow handlers | Base topic, instance name, device name and action sequences arrive from the frontend |
| Stored subentry data to Script engine | Saved actions are executed later with full local privileges |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-06 | Tampering | hub flow base_topic | high | mitigate | validate_base_topic rejects wildcards, edge slashes, empty levels, $-prefixed first level and NUL; no reconfigure step exists for the base topic; per-device subscriptions therefore never widen |
| T-01-07 | Elevation of privilege | stored action sequences | high | mitigate | cv.SCRIPT_SCHEMA plus async_validate_actions_config run before a subentry is created or updated; RAW list stored; the runner validates again when it builds each Script (plan 01-02 runner) |
| T-01-08 | Elevation of privilege | flow endpoints | low | accept | Home Assistant itself restricts config flows and subentry flows to administrators; no additional authentication surface exists in this integration |
| T-01-09 | Information disclosure | validation error text shown in the form | low | mitigate | Error text is truncated to 200 characters and the submitted action data is never echoed into placeholders or logs |
| T-01-SC | Tampering | package installs | low | accept | This plan installs nothing; toolchain locked in plan 01-01 |
</threat_model>
