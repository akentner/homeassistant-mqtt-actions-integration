## Phase Goal

**As a** user with several HA instances, **I want** devices created on one instance to appear on the others once I approve them, **so that** every instance runs the actions locally.

This plan's slice: mirrors go away when, and only when, the owner really removed the device.

<objective>
Remove mirrors on a live tombstone including leftover registry entries (D-09) and on a grace-window prune that is gated by the owner's availability (D-10), with a timer that is armed after setup, reconnect and owner-online events.

Purpose: SYN-05. A follower must never delete a device because a message is merely absent; deletion follows a tombstone or a prune that has positive evidence.

Output: changes in `sync.py`, `manager.py`, `const.py`, a restart helper in `tests/fake_broker.py` and the tests named in the tasks. Implements D-09, D-10 and the tombstone half of D-16 as seen by followers.
</objective>

## Assumptions and defaults (visible, not silent; none are locked decisions, confirm at review)

- **Live-entity guard (planner's reading of D-09 and Pitfall 10):** "leftover entity/device registry entries" are entries whose entities are not live in core. An entity counts as live when `hass.states` has a state for it that is not flagged `restored`. This differs from blindly removing the device: it avoids a forged tombstone making core clear the owner's discovery on every instance. When the owner deletes a device the discovery clear arrives first and core already removed the entities, so nothing is left to clean; leftovers exist when this instance was offline or had discovery disabled during the delete, which is exactly the case the guard lets through.
- **A2 tunable:** `PRUNE_GRACE_SECONDS = 30.0`.
- **A10 (Open Question 3 of RESEARCH, not one of the orchestrator's six defaults):** approvals are not retained after a tombstone. A forged tombstone forces re-approval; the owner's republish restores the mirror unapproved. Accepted per D-09, documented in the README (plan 03-07); a short approval retention is not built.
- **Reconnect forgets presence:** after a reconnect the availability cache is cleared and rebuilt from the broker's replay, so a wiped broker looks like an unknown owner, never an online one.
- **Stale retained online:** the integration has no Last Will, so a crashed owner leaves `online` behind; combined with a missing document that means the owner removed the device, which is the harmless direction.
- **Self-derived edge cases (no SPEC.md exists, the spec-less probe was not run):** the prohibitions above and the behavior edge cases were authored by the planner from RESEARCH and CONTEXT.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Broker to follower tombstone handler | An empty payload carries no owner, so anyone with write access can remove mirrors |
| Broker availability to prune decision | Availability topics decide whether absence means deletion |
| Follower to core registries | Removing registry entries can make core clear retained discovery |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-20 | Denial of service | a forged tombstone removes followers' mirrors and their approvals | medium | accept | Accepted per D-09: the owner republishes its document (plan 03-02) and the mirror returns unapproved, so the worst case is a forced re-approval; the README and the ACL document (plan 03-07) name the broker ACL as the control; no approval retention is built (A10) |
| T-03-21 | Tampering | a prune that deletes a mirror on absence alone (wiped broker, owner offline, stale cache) | high | mitigate | Seen-set since the last reconnect, presence cache reset on reconnect, owner must be online, owner publishes documents before `online` (`test_wiped_broker_heals_without_pruning`) |
| T-03-22 | Denial of service | registry cleanup makes core clear the discovery topic for every instance | high | mitigate | Live-entity guard: cleanup only removes entries without live entities, and only when an MQTT entry exists (`test_live_entities_keep_their_registry_entries`) |
| T-03-23 | Tampering | a stale retained `online` after an owner crash combined with a missing document | low | accept | No Last Will exists (known limitation, AVL-01 deferred); the combination means the owner removed the device, the harmless direction |
| T-03-SC | Tampering | package installs | low | accept | This plan installs nothing; no dependency is added |
