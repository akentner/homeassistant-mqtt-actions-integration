## Decisions this plan implements (visible, not silent)

- **D-01:** main is the release line. This plan fast-forwards main to the phase branch, which adds .planning commits only. From then on every Phase 9 commit lands on main. The phase branch is not used again and is not merged back.
- **D-03:** the bump commit changes only the version line.
- **D-07:** ha-c stays stopped.
- **D-08:** preflight works as in Phase 8 (`preflight.sh stage1`, `stage2`, `check-preflight.sh`). In addition, a registry backup is taken to `~/ha-test/_backup-pre-phase9-<UTC stamp>` (mode 0700) while both instances are stopped. The pin check proves the mount equals the bump SHA, and that SHA goes into `build.txt`.
- **D-09:** lib.sh is not edited. The Phase 9 evidence root comes from `PHASE8_EVIDENCE_ROOT`, the override that `evidence_root()` already honours. `PHASE8_EV_SUFFIX` stays unset, so the folders are `uat-02/` and `uat-04/`. `reseed-tombstones.sh` gets a path-only parametrization with Phase 8 defaults, and the diff is recorded.
- **Planner decisions (Claude's discretion, documented):** (1) D-12's `preflight/` folder is realized as `00-preflight/`, because the unchanged `preflight.sh`, `check-preflight.sh`, `check-uat02.sh` and `check-stale-anchor.sh` read and write that fixed name, and renaming it would edit a check script for no gain. (2) CI runs before the bench run. The owner pushes the bump SHA right after this plan (09-02), so a red CI on code that never ran on GitHub stops the phase before a bench cycle is spent. (3) The owner pushes the exact SHA with a refspec (`git push origin <bump-sha>:refs/heads/main`). Local main already carries evidence commits on top of the bump, and a plain `git push origin main` would make CI run on a docs commit instead of the bump SHA (D-04). (4) The tracer leads with a red gate. `check-preflight.sh` against the empty Phase 9 root must fail before the pin and pass after it, which proves the env file really points the unchanged scripts at the Phase 9 tree.
